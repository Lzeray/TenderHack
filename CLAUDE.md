# CLAUDE.md

Инструкции для Claude при работе с этим репозиторием.

## Проект

MVP для TenderHack: подбор конечного кода КТРУ по русскоязычному описанию товара.
Цепочка: описание → нормализованные характеристики → совместимые позиции → уточнения → код.
Направления — одежда (ОКПД2 `14.`), мебель (`31.`), инструменты (`25.73`, `28.24`).

Подробности:

- `README.md` — запуск, API, правила, результаты;
- `docs/DATA.md` — структура XML КТРУ и решения импорта;
- `docs/process.bpmn` — схема процесса;
- `WORKLOG.md` — журнал работы. Обновляй его после значимых изменений.

## Жёсткие ограничения постановки

- Никаких LLM, embeddings, RAG, нейросетевого ранжирования, внешних платных или проприетарных API, low-code.
- Решения детерминированные и объяснимые: у каждой проверки есть причина в ответе.
- Числа — только `Decimal`. Неявного округления на границах нет. Опечатки в числах и единицах не исправляются.
- `unknown` не считается `valid`. Ограничения пользователя автоматически не ослабляются.
- Шаблон (`isTemplate`) не бывает конечным результатом. Единственный результат в top-K не доказывает уникальность.
- Не выдумывай метрики и не заявляй готовность того, что не запускалось.
  Каталожные smoke-тесты — это не оценка точности.

## Команды

```bash
pip install -r requirements.txt
python -m ktru_assist.cli import --src "КТРУ/КТРУ xml/КТРУ" --db data/ktru.sqlite --as-of 2026-10-09
python -m ktru_assist.cli serve --port 8000      # UI: http://127.0.0.1:8000
python -m pytest -q                              # fixture-тесты + smoke на реальной базе (если она есть)
python -m eval.run_eval --repeat 20              # eval/cases.jsonl → reports/eval_results.json
python -m eval.run_eval --cases eval/holdout.jsonl --out reports/holdout_results.json
```

Отладка: `tools/try_queries.py`, `tools/family.py` (семейство позиций по наименованию), `tools/sql.py`.

## Окружение (Windows, PowerShell 5.1)

- Консоль портит кириллицу. Пиши вывод скриптов в UTF-8-файл и читай его через Read
  (`python -X utf8 tools/... OUT.txt`). Не передавай кириллицу в `python -c`.
- Docker на машине разработчика нет: OpenSearch-бэкенд и `docker-compose.yml` не проверены.
- Тяжёлые LLM локально не запускать. Обычные прогоны (импорт, тесты, eval) допустимы.
- Не устанавливай новые пакеты и браузеры без согласия пользователя.

## Git

- Не коммить и не пушь сам: давай пользователю готовые команды. Remote — `origin`, ветка `main`.
- В git не попадают исходные данные организаторов (`КТРУ/`, `Примеры выгрузок/`) и `data/*.sqlite`
  (см. `.gitignore`). Не изменяй исходные материалы организаторов.

## Структура кода

`ktru_assist/`:

- `catalog/importer.py` — импорт XML. Порядок: последняя версия → статус → сроки на `as_of`.
  Not-actual пропускаются, вложенные zip поддерживаются.
- `catalog/repository.py` — SQLite только на чтение, `Interval`, `merge_intervals`.
- `nlp/normalize.py`, `nlp/typos.py`, `nlp/extract.py` — разбор запроса.
- `units.py` — ОКЕИ и точный перевод внутри одной размерности (В ≠ Вт).
- `search/` — `LocalBM25Backend` (по умолчанию) и `OpenSearchBackend` с одинаковым интерфейсом.
- `validate.py`, `rank.py`, `clarify.py`, `engine.py` — проверка, сортировка, вопрос, решение.
- `api.py`, `web/` — FastAPI и интерфейс на HTML/CSS/JS.

`data/aliases.json` — только проверенные алиасы типа. Цель алиаса должна существовать в каталоге:
это проверяет `tests/test_catalog_real.py`.

## Правила изменений

- Если правка меняет поведение модуля, подними его версию в `config.VERSIONS`.
- Новое поведение покрывай тестом на fixture (`tests/fixture_ktru.py` — синтетика, коды начинаются с 9).
- После правок прогоняй `pytest` и `eval`. Если меняются цифры, обнови их в README.
- Не правь кейсы отложенного набора (`eval/holdout.jsonl`) под поведение системы.
