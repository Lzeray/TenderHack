# CLAUDE.md

Инструкции для Claude при работе с этим репозиторием.

## Проект

MVP для TenderHack: подбор конечного кода КТРУ по русскоязычному описанию товара.
Цепочка: описание → нормализованные характеристики → совместимые позиции → уточнения → код.
Направления — одежда (ОКПД2 `14.`), мебель (`31.`), инструменты (`25.73`, `28.24`).

Подробности:

- `README.md` — запуск, API, правила, результаты;
- `docs/DATA.md` — структура XML КТРУ и решения импорта;
- `docs/process.bpmn` — схема процесса;
- `WORKLOG.md` — журнал работы. Обновляй его после значимых изменений.

## Правила хакатона (методичка организаторов, 09.10.2026)

Тема кейса: «Автозаполнение ключевых характеристик в СТЕ». Категории: одежда, мебель, инструменты.

### Что должна делать система

- По описанию товара на естественном языке (с опечатками и неполными данными) определять
  подходящие характеристики, сопоставлять значения и единицы измерения, приводить их к унифицированному виду.
- Поэтапно сужать множество позиций КТРУ по мере ввода характеристик до конкретного конечного кода.
- Если КТРУ однозначно не определяется — уведомить пользователя и предложить конкретные шаги:
  что дополнить или исправить.
- Находить ошибки в характеристиках (опечатки, явные несоответствия, несуществующие значения),
  указывать на них и объяснять, почему характеристика некорректна и какие нужно добавить.
- В интерфейсе показывать, какие характеристики унифицированы, какие значения и единицы сопоставлены,
  и ход подбора кода в реальном времени.
- Иметь удобный веб-интерфейс, предусматривать масштабирование, быть протестированной на реальных кейсах,
  в том числе с неполными и некорректными данными.
- Сопровождаться схемой реализации в нотации BPMN (`docs/process.bpmn`).

### Ограничения регламента

1. Решение работает на Linux и предоставляет веб-интерфейс.
2. Запрещены платные поисковые API (Yandex Search API, Google Custom Search JSON API и подобные)
   и внешние API проприетарных LLM (OpenAI GPT, Google Gemini, Anthropic Claude и подобные).
3. Запрещены low-code и no-code платформы.
4. Разрешены только открытые ML-модели и нейросети, суммарно не больше 40 ГБ VRAM на инференс.
   Выбор должен быть соразмерен задаче: предпочтение лёгким и быстрым решениям,
   необоснованно «тяжёлые» модели снижают оценку.
5. Допускаются роутеры для LLM (timeweb, selectel и т. п.), предпочтение отечественным.

## Жёсткие ограничения постановки

Это решения команды. С 10.10.2026 (план улучшений `docs/PLAN.md`) разрешены **только локальные открытые модели
за флагами**: один лёгкий энкодер (A-semantic) и один локальный LLM-разбор по эскалации (B). По умолчанию
они выключены; детерминированное ядро остаётся основным путём и единственным судьёй соответствия КТРУ.

- Никаких внешних API (в том числе LLM-роутеров), RAG по всему каталогу, нейросетевого ранжирования, low-code.
- Выход модели — только предложение: он не меняет числа, единицы и отрицания из текста, не выбирает код
  и не даёт `matched` без подтверждения пользователем (см. `ktru_assist/resolver.py`).
- При выключенных или недоступных моделях система работает так же, как ядро без моделей.
- Решения детерминированные и объяснимые: у каждой проверки есть причина в ответе.
- Числа — только `Decimal`. Неявного округления на границах нет. Опечатки в числах и единицах не исправляются.
- `unknown` не считается `valid`. Ограничения пользователя автоматически не ослабляются.
- Шаблон (`isTemplate`) не бывает конечным результатом. Единственный результат в top-K не доказывает уникальность.
- Не выдумывай метрики и не заявляй готовность того, что не запускалось.
  Каталожные smoke-тесты — это не оценка точности.

## Команды

```bash
pip install -r requirements.txt
python -m ktru_assist.cli import --src "КТРУ/КТРУ xml/КТРУ" --db data/ktru.sqlite --as-of 2026-10-09
python -m ktru_assist.cli serve --port 8000      # UI: http://127.0.0.1:8000
python -m pytest -q                              # fixture-тесты + smoke на реальной базе (если она есть)
python -m eval.run_eval --repeat 20              # eval/cases.jsonl → reports/eval_results.json
python -m eval.run_eval --cases eval/holdout.jsonl --out reports/holdout_results.json
```

## Структура кода

`ktru_assist/`:

- `catalog/importer.py` — импорт XML. Порядок: последняя версия → статус → сроки на `as_of`.
  Not-actual пропускаются, вложенные zip поддерживаются.
- `catalog/repository.py` — SQLite только на чтение, `Interval`, `merge_intervals`.
- `nlp/normalize.py`, `nlp/typos.py`, `nlp/extract.py` — разбор запроса.
- `units.py` — ОКЕИ и точный перевод внутри одной размерности (В ≠ Вт).
- `search/` — `LocalBM25Backend` (по умолчанию) и `OpenSearchBackend` с одинаковым интерфейсом.
- `validate.py`, `rank.py`, `clarify.py`, `engine.py` — проверка, сортировка, вопрос, решение.
- `registry.py`, `components.py`, `plausibility.py`, `resolver.py` — реестр типов, части товара,
  правдоподобие, согласование источников (ручное > правила > модели).
- `orchestrator.py` — пути A/B, эскалация, revision/stale, кэши, журнал; `semantic/` — rubert-tiny2 на numpy;
  `llm/` — контекст из снимка, Ollama, проверка ответа. Контракты — `docs/CONTRACTS.md`.
- `api.py`, `web/` — FastAPI и интерфейс на HTML/CSS/JS (`web/state.js` — правила применения ответов).
- `eval/` — `run_eval.py` (MVP-метрики), `run_benchmark.py` (сравнение конфигураций), `synth.py`, `SCHEMA.md`.
- `experiments/` — стресс-набор, аблации, бесловарные стеммеры, прогон по реальным СТЕ, сравнение отчётов
  по кейсам (`docs/EXPERIMENTS.md`). Отчёты пиши в `reports/exp/`; вывод не направляй в файл, который сам читается
  маской (так однажды заполнился диск).
- `morph.py` — бесловарный стеммер для `KTRU_MORPH=snowball`; литералы слов в коде приводи через `text.lemma_set`.

`data/aliases.json` — только проверенные алиасы типа (значение — главное слово или список трактовок).
`data/value_aliases.json` — алиасы значений с контекстом свойства. Цели обоих должны существовать в каталоге:
это проверяет `tests/test_catalog_real.py`.

## Правила изменений

- Если правка меняет поведение модуля, подними его версию в `config.VERSIONS`.
- Новое поведение покрывай тестом на fixture (`tests/fixture_ktru.py` — синтетика, коды начинаются с 9).
- После правок прогоняй `pytest` и `eval`. Если меняются цифры, обнови их в README.
- Не правь кейсы отложенного набора (`eval/holdout.jsonl`) под поведение системы.
