# Бенчмарк подбора КТРУ

Система оценивается на одном наборе: **313 кейсов** `independent/suites/natural.jsonl`. Это замороженная test-часть
независимого набора v2: эталон посчитан отдельным кодом прямо по `data/ktru.sqlite` (`independent/reference.py`),
под эти кейсы система не настраивалась. Хеш набора — `independent/test_manifest.sha256`; прогон сверяет его сам.

Остальные наборы (dev-часть `natural`, `contradictions`, `out_of_scope`, метаморфные, общий набор v1) удалены
10.10.2026; они есть в истории git.

```bash
python -m benchmark.independent.run --adapters ktru:core --no-baselines --suites natural \
    --hide-test-cases --out reports/bench/natural_test.json
```

`--hide-test-cases` убирает строки кейсов из отчёта: по test смотрим только агрегаты. Если смотрели кейс, это нужно
отметить в отчёте.

## Метрики, которые показываем

| Метрика | Поле отчёта | Смысл |
|---|---|---|
| Верный код сразу | `code_reached@0` | код выдан без вопросов и он верный |
| Точность выданных кодов | `auto_precision`, `wrong_auto` | доля верных среди выданных сразу кодов; число неверных |
| Верный код за ≤ 2 вопроса | `code_reached@2` | симуляция пользователя, отвечающего верно (верхняя граница) |
| Вопросы, не сузившие список | `ranking.useless_question_rate` | доля вопросов, после которых список позиций не сократился |

Остальные поля отчёта описаны в `independent/README.md`. `hit@1` и `mrr` в презентации не используем: когда кода
по описанию однозначно не определить, первая строка списка зависит от порядка сортировки, а засчитывается любой
из допустимых кодов.

Адаптеры решений — `adapters/` (`ktru:core` — ядро без моделей). Чужое решение подключается так же:
скопируйте `adapters/template.py` и реализуйте `predict()`.
