# Метаморфные и состязательные наборы v1

Эти наборы проверяют сценарии, которых нет ни в `benchmark/suites`, ни в независимых наборах `benchmark/independent`:

- устойчивость к форме записи, которая не меняет смысл;
- инструкции, вставленные в описание товара;
- реквизиты закупки рядом с описанием;
- несколько товаров в одном запросе;
- монотонность сужения;
- вырожденные запросы;
- человеческие опечатки («стур», «атвертка», «одфертуа», «колоши») и ошибки в числах («010», «0180 мм», «1 80 мм»);
- небрежный и ленивый ввод: слитные слова, числа без единиц, «больше 120», «меньше 500», «больше 120 но меньше 500»,
  «120-500», телеграфный стиль.

Генератор `generate.py` **не читает базу КТРУ и не запускает систему**. Эталон каждого кейса получается одним из двух способов:

- **Наследуется** от исходного кейса `benchmark/independent/suites/natural.jsonl`. Эталон того кейса посчитан по базе (`reference.py`), а преобразование его не меняет.
- **Пуст по построению.** Это кейсы, где по одному коду нельзя ответить: два товара сразу или товара нет вовсе.

Поэтому наборы можно пересобрать и проверить без `data/ktru.sqlite`.

### Опечатки и ошибки в числах: как построены

- Опечатка ставится в первое слово наименования, если оно стоит в тексте отдельным словом. Проверки:
  получившегося слова нет в словаре pymorphy3 («стал», «стел» отбрасываются), а ближайшее к нему слово
  среди слов наименований каталога (272 наименования из наборов) — исходное, и оно единственное.
  Расстояние — Дамерау–Левенштейн.
- Не больше 4 кейсов на одно слово.
- «Отвертки» среди наименований наборов нет. Поэтому у «одфертуа» эталон пуст: правильный ответ —
  не выдавать код без подтверждения.
- В числах ошибка вносится ровно в одно число факта. «0,5» — не ошибка: ведущий ноль считается ошибкой
  только у целого числа.

Пробный прогон MVP (`ktru:core`, `main`) на синтетическом каталоге из тестов (`tests/fixture_ktru.py`).
Это смоук, а не оценка:

- «пассатижи слесарные 0180 мм» → код, длина принята как 180;
- «1 80 мм» → код, длина 80 мм;
- «18,,0 см» → код, длина 0 см;
- «l80 мм» → уточнение;
- «пасотижи», «пассатишы», «стур на металлическом каркасе…» → тот же код, что без опечатки;
- «посатижы», «одфертуа», «колоши» → `not_found`.

### Ленивые числа по каталогу (`lazy_numbers`)

Строгое «больше 120» и двустороннее «больше 120, но меньше 500» меняют эталон: какие позиции подходят, зависит от
диапазонов в каталоге. Поэтому этот набор строится по базе — `lazy_numbers.py`, эталон тем же `reference.py`.

```bash
python -m benchmark.metamorphic.lazy_numbers --db data/ktru.sqlite    # → suites/lazy_numbers.jsonl + строка манифеста
python -m benchmark.metamorphic.lazy_numbers --fixture                 # → fixture/suites/lazy_numbers_fixture.jsonl
```

Для каждого семейства (до 30 на направление на реальной базе) берётся одна числовая характеристика с одной единицей
у всех значений и границы её диапазонов `b0 < … < bn`; `a` и `b` — границы на трети и двух третях списка.
К тексту добавляются обязательные и `kind=1` характеристики целевой позиции с единственным значением.

| Вариант | Запись | Смысл | `same_as` |
|---|---|---|---|
| `point_unit` / `point_no_unit` | «рост 173 см» / «рост 173» | x = точка внутри значения позиции; без единицы — в единице каталога | `point_unit` |
| `gt` / `gt_no_unit` | «больше 1000 мм» / «больше 1000» | x > a | `gt` |
| `lt` | «меньше 1400 мм» | x < b | |
| `gt_lt` / `gt_lt_no_unit` / `symbols` | «больше 1000, но меньше 1400 мм» / «больше 1000 меньше 1400» / «>1000 <1400 мм» | a < x < b | `gt_lt` |
| `ge_le` / `dash_range` | «не меньше 1000 и не больше 1400 мм» / «1000-1400 мм» | a ≤ x ≤ b | `ge_le` |
| `gt_max` / `lt_min` | «больше 1800 мм» / «меньше 600 мм» | за крайними границами: строгое сравнение | |
| `inverted` | «больше 1400, но меньше 1000 мм» | пустой интервал — кода нет | |
| `gap` | «больше 164, но меньше 170 см» | разрыв между значениями семейства — кода нет | |
| `no_property` | «…, больше 1000, но меньше 1400 мм» | свойство не названо; только если числовая характеристика у семейства одна | `gt_lt` |

Позиция подходит, если хотя бы одно её значение пересекается с интервалом условия (как `>=`/`<=` в независимых
наборах). «a-b» считается закрытым интервалом — это решение набора, а не системы.

**На реальной базе набор построен** (10.10.2026, снимок `nsiKTRUNew_all_actual_20261003020003`): `suites/lazy_numbers.jsonl`,
1173 кейса, из них 304 в test; строка манифеста добавлена. Прогон веток — `reports/bench/branches_2026-10-10/RESULTS.md`.
Тест `test_gold_recomputed_on_real_catalog` при наличии базы пересчитывает эталон всех наборов этой папки,
в том числе `no_unit` и `telegraph`: они опираются на допущение, что у характеристики одна единица у всех значений.

**Синтетический каталог** (`fixture_catalog.py`, 4 семейства, коды с 9, не реальные данные) нужен, чтобы проверить
генератор и прогнать систему без базы. Отчёт MVP (`ktru:core`, ветка `main`) на нём —
`reports/bench/metamorphic/mvp_core_lazy_numbers_fixture*.md`: 56 кейсов, 24 автокода, из них 13 неверных;
hit@1 = 0,4, hit@3 = 0,778, эталона нет в списке в 22% кейсов, `useless_question_rate` = 0,553.
Система принимает «больше N» и «меньше N» за точное значение N. Например, «мощность меньше 800 Вт» →
позиция «от 800 Вт», «длина столешницы больше 1800 мм» → позиция «1400–1800 мм». Это смоук на синтетике,
а не оценка точности.

### Как выбираются исходные кейсы и строятся сплиты

- **Опечатки.** Кейсы `natural` с опечаткой (`variant` содержит `typo`) в источники не берутся, чтобы эффекты не смешивались.
- **Выбор кейсов.** Кейсы для каждого приёма выбираются детерминированно: сортировка по sha256 от id с солью `mm1-a`.
- **Сплит.** Сплит наследуется от исходного кейса, то есть от наименования позиции. Поэтому тексты test-кейсов `natural` не попадают в dev.
- **Пары в `multi_item`.** Оба товара пары берутся из одного сплита.
- **`edge_inputs`.** Сплит считается по sha256 текста с той же солью.

### Почему эталон корректен

- **`invariance`, `procurement_noise`, `monotonicity`.** Факты в тексте остаются теми же, поэтому эталон исходного кейса сохраняется. Исключение — `unit_equiv`: значение переводится точно, в `Decimal`, внутри одной величины, и факт в кейсе обновлён. Эталон `reference.py` от такого перевода не меняется.
- **`injection`.** Вставленный код — позиция того же наименования, которая не входит в эталон: сначала берётся из `forbidden_codes` исходного кейса, иначе из эталонов других кейсов того же наименования.
- **`monotonicity`.** Эталон полного описания ⊆ эталона голого наименования. Голое наименование берётся без характеристик и без шума. Это свойство проверяет тест.
- **`multi_item`, `edge_inputs`.** Один код КТРУ не может описать два товара или отсутствие товара.

## Запуск

```bash
python -m benchmark.metamorphic.generate --stats     # распределение
python -m benchmark.metamorphic.generate             # пересобрать suites/ и сверить test с манифестом
python -m benchmark.metamorphic.lazy_numbers --db data/ktru.sqlite   # набор ленивых чисел по базе

# система на синтетическом каталоге (без реальной базы)
python -m benchmark.metamorphic.fixture_catalog data/bench_fixture   # → data/bench_fixture/bench_fixture.sqlite
KTRU_DB=data/bench_fixture/bench_fixture.sqlite python -m benchmark.run --adapter ktru:core --dialog \
    --suites benchmark/metamorphic/fixture/suites/lazy_numbers_fixture.jsonl --out reports/bench/lazy_fixture.json

# формат benchmark/README.md: pass_rate, forbidden_code_hits, checks_by_type (same_as, subset_of)
python -m benchmark.run --adapter ktru:core --out reports/bench/metamorphic.json \
    --suites benchmark/metamorphic/suites/invariance.jsonl benchmark/metamorphic/suites/injection.jsonl \
             benchmark/metamorphic/suites/procurement_noise.jsonl benchmark/metamorphic/suites/multi_item.jsonl \
             benchmark/metamorphic/suites/monotonicity.jsonl benchmark/metamorphic/suites/edge_inputs.jsonl

# метрики v2: wrong_auto, required_hit, no_code_respected, code_reached@k и тривиальные базовые линии
python -m benchmark.independent.run --adapters ktru:core --suites benchmark/metamorphic/suites/*.jsonl \
    --out reports/bench/metamorphic_v2.json

python -m pytest -q tests/test_metamorphic_suites.py
```

В PowerShell переменную задают так: `$env:KTRU_DB = "data\bench_fixture\bench_fixture.sqlite"`.

Проверки `same_as` и `subset_of` считает только `benchmark.run`. Они видны в `checks_by_type`. Метрики v2 их не видят. Поэтому для `invariance`, `injection`, `procurement_noise` и `monotonicity` нужны оба отчёта:

- v2 показывает, не стал ли код ошибочным;
- `same_as` показывает, не изменился ли ответ от формы записи.

## Заморозка

Хеши test-частей лежат в `test_manifest.sha256` (синтетический набор — в `fixture/test_manifest.sha256`). Их сверяют три места:

- `python -m benchmark.independent.run` — результат в `meta.frozen`;
- тест `test_files_match_generator_and_manifest`;
- сам генератор.

Правила те же, что в `benchmark/independent/FROZEN.md`:

- по test смотрим только агрегаты;
- настройка идёт только на dev;
- если test-часть изменилась, это новая версия наборов (v2) с новым манифестом.

Наборы построены из `natural.jsonl` v2. Если `natural` пересоберут, пересоберите и эти наборы как новую версию.

## Ограничения

- **Наборы синтетические.** Сами формулировки взяты из `natural`, у которого свои ограничения (см. `benchmark/independent/README.md`).
- **`invariance/homoglyph` и `invariance/upper` строже остальных приёмов.** Решение, которое не нормализует латинские двойники или верхний регистр, получит уточнение вместо кода. Такой результат — потеря полезности, а не ошибка безопасности. Это видно по `same_as` и `required_hit`; `wrong_auto` от этого не растёт.
- **Реквизиты закупки подобраны так, чтобы не совпадать с характеристиками КТРУ**: дни, рубли, номера. Но ни один реквизит не сверялся с полным списком характеристик каждого семейства, потому что генератор не читает базу.
- **Граничных значений (ровно на границе диапазона, включённой или нет) здесь нет.** Для них нужны диапазоны из базы. Такие кейсы лучше добавить в `benchmark/independent/generate.py`.
- **Наборы из `natural` и `lazy_numbers` по реальной базе ни разу не прогонялись на нашей системе**: в среде, где они
  построены, нет `data/ktru.sqlite`. Система запускалась только на синтетическом `lazy_numbers_fixture`.
- **Словарь для проверки опечаток неполный.** Ближайшее слово ищется только среди слов наименований из наборов,
  а не всего каталога. Тест `test_gold_recomputed_on_real_catalog` эталон пересчитывает, но словарь не проверяет.
- **`glued_words` строже большинства приёмов.** Разбор слитных слов требует словаря. Если решение не умеет
  разбирать слитное написание, оно получит уточнение вместо кода: `same_as` и `required_hit` упадут, а `wrong_auto`
  расти не должен.
- **`telegraph` проверяет только безопасность и диалог.** Без названий свойств текст может быть неоднозначным,
  поэтому `code_required` там не ставится.
- **Строгость «больше»/«меньше» — решение набора.** В закупках «более» обычно строгое, «не менее» — нет. Если команда
  решит иначе, меняется `lazy_numbers.py`, и это новая версия набора.
