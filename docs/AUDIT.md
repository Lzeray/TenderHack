## Расхождения и пробелы (что меняем)

1. **Тип по главному слову.** `Engine._detect_heads` берёт главное слово наименования КТРУ из текста.
   Составных названий и альтернатив нет: алиас указывает ровно на одно главное слово.
   Если тип не найден, модель не предлагает варианты — сразу возвращается `not_found`.
2. **Алиасов значений нет.** Например, «сетевой» не сопоставляется с «От сети». Это отмечено в README
   как известное ограничение.
3. **Части товара не различаются.** Значение привязывается к свойству, только если *все* слова названия свойства
   стоят рядом. Если пользователь пишет «чёрный каркас, красное сиденье», а слова «цвет» в тексте нет,
   значение получает статус `ambiguous` или привязывается по совпадению значения. Компонент («каркас», «сиденье»)
   отдельно не хранится.
4. **Нет проверок правдоподобия.** Значение «45 м» проходит открытый интервал и не даёт предупреждения.
5. **Нет версии запроса (revision) и стадий.** Устаревшие ответы клиент отбрасывает по локальному счётчику `seq`,
   сервер о версиях ничего не знает. Задержка ввода (debounce) — 600 мс, план требует 100–150 мс.
   Нет отправки по Enter, нет состояний «черновик / отправлено / устарело».
6. **Нет координат в исходном тексте.** `Feature.span` указывает на *нормализованный* текст
   (после «75см» → «75 см»), а не на `raw_query`.
7. **Нет журнала событий и раздельных задержек.** Есть только `elapsed_ms` и `eval/run_eval.py`.
   Нет метрик `incorrect_matched` и `unsafe_matched`, нет покрытия автоматизацией и замера памяти.
8. **Моделей нет.** Слоёв A-semantic и B нет, контекста из каталога для модели нет.

## Текущая семантика `matched` (её сохраняем)

`engine.search` выдаёт `matched`, только если одновременно выполнено всё ниже:

- осталась ровно одна совместимая конечная позиция, не шаблон (`finals == 1`);
- тип подтверждён (`type_confirmed`): все слова наименования есть в описании и наименование одно,
  в области одно наименование, либо тип выбран пользователем;
- область типа выбрана исчерпывающе (`res_b.complete`) — все активные позиции с этим главным словом;
- нет неоднозначных признаков и неоднозначных опечаток;
- у позиции нет блокирующих проверок (`ev.blocking`): `unknown` у существующего свойства
  и **незаполненные обязательные свойства**.

Значит, сейчас `matched` означает сразу две вещи: «код однозначен» и «обязательные характеристики заполнены».
План требует разделить это на `code_resolution` и `characteristics_completion`. Поле `status` сохраняем
без изменения смысла, новые поля добавляем рядом (см. `docs/CONTRACTS.md`).
