# Данные КТРУ: структура и решения импорта

## Источник

`КТРУ/КТРУ xml.zip` → 183 вложенных архива `NNN_nsiKTRUNew_all_2026-10-05.zip`, в каждом один XML:

- **161–242:** `nsiKTRUNew_all_actual_20261003020003_001…082.xml` — 82 файла, по 1000 позиций (в последнем 465);
- **243–343:** `nsiKTRUNew_all_not-actual_20261003020635_001…101.xml` — 101 файл. Эти архивы удалены
  из распакованной папки по просьбе заказчика; импортёр их в любом случае пропускает.

Обзор всех путей элементов и перечислений: `tools/survey_ktru.py`, результат — `reports/survey_full.txt`.
Описание полей — `КТРУ/Описание структуры xml с КТРУ.docx`, раздел nsiKTRU.

## Наблюдения (actual-часть, 81 465 записей)

- **Статусы.** `ACTIVE` — 60 087, `TERMINATED` — 21 376 (в схеме есть ещё `INACTIVE`).
  Имя файла `actual` не гарантирует активность.
- **Повторы кодов.** У 2 кодов по 2 записи разных версий.
- **Сроки применения.** `applicationDateEnd` задан у 34 позиций; есть позиции с началом применения в будущем.
- **Шаблоны.** `isTemplate=true` у 6 150 позиций (укрупнённые). Конечные позиции ссылаются на шаблон через
  `parentPositionInfo(code, version)`. В 21 461 случае версия ссылки не совпадает с версией шаблона в снимке;
  это фиксируется в `import_issues`, связь не «чинится».
- **Характеристики.**
  - `type`: 1 — качественная, 2 — количественная.
  - `kind`: 1 — неизменяемая (обычно отличает конечные позиции семейства), 2 / 3 — выбор одного или нескольких значений.
  - `isRequired`.
- **Значения** бывают трёх видов:
  - `qualityDescription`;
  - диапазон `rangeSet/valueRange` с `min` / `max` и знаками `greater`, `greaterOrEqual`, `less`, `lessOrEqual`
    (любая из границ может отсутствовать);
  - конкретное число `valueSet/concreteValue`.

  ОКЕИ у числового значения может отсутствовать — тогда единица иногда указана в названии свойства
  («Момент (Нм)», «Плотность, г/м2»).
- **Размеры одежды** («Российский размер») заданы в основном как текстовые значения «44», «46-48».

## Правила импорта

1. Читаются XML, в имени которых есть `actual`, но нет `not-actual` / `not_actual`. Вложенные zip поддерживаются.
2. Для каждого кода выбирается запись с максимальным `version`; при равенстве — по `updateDate`, `publishDate`
   и имени файла. Остальные записи сохраняются в `dropped_records`.
3. Затем вычисляется применимость на дату `--as-of`: `status == ACTIVE`, начало применения не позже `as_of`,
   окончание (если есть) не раньше `as_of`. Причина неактивности — в `inactive_reason`.
4. Числа хранятся строками `Decimal` — без потери точности.
5. Характеристики сохраняются для направлений MVP. Для остальных — только заголовок позиции
   (`--all-characteristics` сохраняет всё).
6. Импорт идемпотентен: база собирается во временный файл и атомарно заменяет старую.
   Повторный импорт даёт тот же результат — это проверяется тестом.

## Критерии направлений MVP

| Направление | Префикс ОКПД2 |
| --- | --- |
| Одежда | `14.` |
| Мебель | `31.` |
| Инструменты | `25.73`, `28.24` |

Рубрикатор КТРУ в данных есть, но для инструментов отдельной рубрики нет: `25.73` разнесён по рубрикам
«Строительные материалы», «Прочее» и др. Рубрика «Одежда и обувь» включает обувь `15.20`, а часть `14.12` лежит
в «Медицинских изделиях». Поэтому критерий — префикс ОКПД2; рубрики сохраняются как справочное поле.

## Excel-выгрузки СТЕ

`Примеры выгрузок/*.xlsx` — около 100 тыс. строк в каждом файле. Колонки: ID СТЕ, наименование, модель,
производитель, страна, характеристики через `|`. Разметки «СТЕ → КТРУ» нет. Использованы только для изучения
формулировок; нормативным источником не являются.
