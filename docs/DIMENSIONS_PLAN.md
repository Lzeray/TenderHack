# Размеры: интервалы, габариты и связанные проблемы

Разбор перед реализацией (10.10.2026). Все примеры — прогоны текущего ядра на реальном снимке КТРУ
(`reports/exp/dims_probe*.txt`, не в git); свойства КТРУ — `reports/exp/dims_ktru.txt`.

## Как КТРУ хранит размеры

Не одним интервалом на позицию, а **набором ступеней** у одной позиции, из которых выбирается одно значение
(вид характеристики 2):

```text
Стол …   Длина: < 1200 мм | ≥ 1200 и < 1400 мм | ≥ 1400 и < 1600 мм | … | ≥ 2200 и < 2500 мм
Пассатижи Длина: < 160 | ≥ 160 и < 180 | ≥ 180 и < 200 | ≥ 200 и < 250 | ≥ 250 и < 300 | ≥ 300 мм
Шкаф     Высота шкафа: … | ≥ 1500 и < 1600 | ≥ 1600 и < 1700 | …
```

Нижняя граница включена, верхняя — нет. В карточку СТЕ записывается одна ступень. Поэтому для размера важно
не только «совместима ли позиция», но и «какую ступень записать».

## Найденные проблемы

### А. Интервалы в запросе

| № | Запрос | Что сейчас | Что не так |
| --- | --- | --- | --- |
| А1 | «пассатижи длина от 180 до 250 мм» | код выдан; проверка `valid`: «ступень ≥ 180 и < 200 целиком удовлетворяет» | диапазон покрывает 2 ступени (и касается третьей в точке 250): какую записать в карточку — не решается и не спрашивается |
| А2 | «длина от 120 до 140 см» при ступенях [120; 140) и [140; 160) | так же, как А1 | диапазон совпадает со ступенью КТРУ, но формально касается следующей одной точкой 140 («до» включительно, у КТРУ «<») |
| А3 | диапазон частично внутри ступени («от 130 до 150 см») | `unknown`: «частично пересекается — нужно точное значение» | правильно не утверждать, но пользователю не показано, какие ступени подходят |
| А4 | «длина 1200–1400 мм» (длинное тире, единица только в конце) | разобрано как «длина 1200» без единицы + «1400 мм» отдельно | диапазон не распознан (с дефисом «160-200 мм» работает) |
| А5 | «длина 1 200 мм» (пробел в тысячах) | «длина 1» + «200 мм» | число разорвано |
| А6 | «длина 140±5 см» | «длина 140» + «5 см», привязанные к толщине | допуск не распознан |
| А7 | «длина около 140 см», «примерно» | как точное 140 | приблизительность потеряна |
| А8 | «размер 48-50» у одежды | «нет свойства размер подходящей размерности» | у дискретного свойства («Российский размер»: 44, 46, 48 …) диапазон = набор значений |

### Б. Габариты «60 на 120 на 70»

| № | Запрос | Что сейчас | Что не так |
| --- | --- | --- | --- |
| Б1 | «стол 1200х600х750 мм», «120 на 60 на 75 см», «габариты 120х60х75 см» | берётся только последнее число и предлагается как **толщина** материала | два числа молча теряются, привязка абсурдна |
| Б2 | «стол 120x60x75» без единицы | не извлекается ничего | молча |

| Б4 | порядок осей | — | соглашения разные: Д×Ш×В, Ш×Г×В, Д×Г×В; явные подписи («ДхШхВ») редки |
| Б5 | одна ось — разные названия у позиций одного типа | «шкаф высота 1,8 м» → у части позиций «свойства нет» | «Высота» / «Высота шкафа», «Глубина» / «Глубина шкафа», «Глубина стеллажа» / «Глубина секции стеллажа» |
| Б6 | у типа нет размеров в КТРУ | «Стол письменный»: только толщины материалов | габариты не могут повлиять на код; проверить их можно только по выгрузкам (уровень 2) |
| Б7 | инструмент «сверло 6х100», «диск 125х22,2», «болт М8х40» | — | «A×B» здесь не оси мебели: диаметр × длина, наружный × посадочный диаметр, резьба × длина |
| Б8 | «в упаковке 120х60х10 см» | «упаковке» как название свойства + 10 см к толщине | размеры упаковки не являются размерами товара |
| Б9 | два числа «120х60» | последнее число — неоднозначно | столешница: длина × ширина, высоты нет |

### В. Единицы

| № | Пример | Проблема |
| --- | --- | --- |
| В1 | «длина 140», «120x60x75» | единицы нет; в КТРУ мм, в речи — см. Уровень 3 уже предлагает единицу по КТРУ для одиночного числа, для габаритов — нет |

## Предлагаемое решение (до подтверждения)

1. **Разбор** (нормализатор и экстрактор): длинное тире и «—» в диапазонах; пробел-разделитель тысяч
   («1 200 мм», только при трёх цифрах после пробела); «140±5» → [135; 145]; «около/примерно X» — признак
   приблизительности (см. вопрос 4); «48-50» у дискретного свойства → набор значений.
2. **Интервал против ступеней КТРУ.** Для числового признака считаем, с какими ступенями позиции он
   пересекается:
   - одна ступень — значение для карточки определено;
   - несколько — вопрос «какой интервал КТРУ записать» только из пересекающихся ступеней (см. вопрос 1);
   - касание соседней ступени только граничной точкой («от 120 до 140» при [120; 140) и [140; 160)) — см. вопрос 2.
   Совместимость позиции (уровень 1) не ослабляется: правила выше решают, какую ступень записать.
3. **Габариты** — отдельный признак «габариты» из 2–3 чисел с единицей:
   - единица: указанная; иначе — та, при которой числа подходят к ступеням КТРУ / типичны по выгрузкам
     (как правило `unit_missing`), неоднозначно — вопрос;
   - оси: явные подписи («ДхШхВ», «длина … ширина … высота») — напрямую; иначе перебор перестановок по
     «общим» размерным свойствам области (Длина/Ширина/Глубина/Высота/Диаметр без частей товара; с названием
     типа — «Высота шкафа»); перестановка проходит, если каждое число допустимо по КТРУ и (если есть статистика)
     типично по выгрузкам; дальше — см. вопрос 3;
   - размеры частей («полки», «ящика», «секции», «антресоли»), толщины и упаковка в оси не попадают;
   - у инструмента «A×B» — только если у типа есть пара свойств подходящих размерностей (диаметр и длина),
     иначе признак остаётся неразобранным с пояснением, а не привязывается к случайному свойству.
4. **Одна ось — разные названия** (Б5): внутри области свойства «Высота» и «Высота <типа>» считаются одной осью
   для габаритов и для явных «высота 1,8 м»: проверка ищет у позиции любое свойство этой оси.
5. **Нет размеров в КТРУ** (Б6): габариты не участвуют в подборе, показываются как «на код не влияет» с оценкой
   по выгрузкам (уже есть для свойств вне КТРУ).

## Решения команды (10.10.2026)

1. **Диапазон задевает несколько ступеней** («от 180 до 250 мм» при 180–200 и 200–250): пользователя устраивают
   все ступени — показываем все позиции, удовлетворяющие диапазону, вопрос о ступени не задаём. Если ступень
   пересекается с диапазоном лишь частично («190–210» и ступень 180–200), позицию тоже показываем, но с
   пометкой, что значение КТРУ шире запроса (включает 180–190).
2. **Касание соседней ступени граничной точкой** («от 120 до 140 см» при [120; 140) и [140; 160)) — это одна
   ступень [120; 140); соседнюю не берём. Касание считается только у диапазона; одиночное «140 см» по-прежнему
   попадает в [140; 160).
3. **Габариты без подписей осей**: если правдоподобна одна раскладка — показываем её («ширина 80, глубина 50,
   высота 180») и учитываем в подборе только после подтверждения одним действием; если несколько — вопрос с
   вариантами раскладки.
4. **«Около / примерно X»** — допуск ±5 % (интервал [0,95·X; 1,05·X], Decimal без округления), дальше как диапазон.

### Область применения (решение 10.10.2026)

Сравнение со ступенями общее для всех чисел, поэтому правила применяются не только к размерам:

| Правило | Где применяется |
| --- | --- |
| диапазон против ступеней, граничная точка, пометка «шире запроса» | все измеряемые величины (есть размерность, кроме штук): длина, масса, мощность, обороты, нагрузка … |
| «около X» = ±5 % | измеряемые величины, кроме штук; у штук «около 3» = 3 с пометкой «указано приблизительно» |
| пометка «шире» у вложенных значений «≥ N» (количество ящиков, длина разводного ключа) | только если ни одно значение не укладывается в запрос целиком — иначе шум у каждой карточки |
| диапазон как набор значений | дискретные числовые свойства (напряжение 10,8 / 12 / 18 В, посадочный диаметр, размер одежды) |
| габариты и оси | только геометрические размеры: длина, ширина, глубина, высота, диаметр |

## Журнал

### D1. Разбор (10.10.2026)

- Нормализатор: «1200–1400» (длинное тире) → «1200-1400»; «1 200 мм» → «1200 мм» (только одна цифра, пробел,
  три цифры и единица длины/массы/мощности/объёма — чтобы не склеить «рост 98 104 см» и «3 100 шт»);
  «140±5» → «от 135 до 145», «600 ± 10 %» → «от 540 до 660»; «~140» → «около 140». Замена может быть
  вычисляемой (`Tracked.sub` принимает функцию), координаты исходного текста сохраняются.
- Экстрактор: «около / примерно / приблизительно / порядка / ориентировочно X» у измеряемой величины —
  интервал [0,95·X; 1,05·X]; у штук — точное X; в пояснении признака «указано приблизительно».

### D2. Диапазон против ступеней КТРУ

`validate.check_numeric`, `numeric_steps`: для диапазона (не точки) ступень «подходит», если лежит в нём
целиком; «частично», если пересекается больше чем в одной точке. Есть подходящие — `valid` со списком ступеней;
только частичные — `valid` с флагом `wider` («значение КТРУ шире запроса»); касание только границей —
`unknown`. В карточке такие совпадения — отдельная группа «Подходит, но значение КТРУ шире запроса».

| Запрос (ступени пассатижей: < 160 / 160–180 / 180–200 / 200–250 …) | Результат |
| --- | --- |
| длина от 180 до 250 мм | подходят 180–200 и 200–250 |
| длина от 190 до 210 мм | совместимо, значение КТРУ шире запроса |
| длина от 160 до 180 мм | подходит 160–180; 180–200 (касание точкой 180) не берётся |
| длина около 180 мм | 171–189: шире запроса (160–180 и 180–200) |
| высота шкафа от 150 до 160 см (ступени 140–160, 160–180) | 140–160, шире запроса; 160–180 не берётся |

Бенчмарк и стресс-набор — без изменений по кейсам (диапазонов в них почти нет); поведение закреплено тестами
`tests/test_engine.py::test_range_*`, `test_approx_*`, `tests/test_text_processing.py::test_dimension_notation_normalization`.

### D3. Одна ось — разные названия

`ktru_assist/dims.py::axis_of`: свойство — общий размер по оси, если после слова-оси (длина, ширина, глубина,
высота, диаметр) идут только слова наименования позиции, «столешница», «изделие», «габаритный», «общий» или
пояснение в скобках. «Глубина секции стеллажа», «Длина полки», «Толщина …» — не общие оси.

- Проверка (`validate.find_prop`): если у позиции нет свойства с тем же названием, берётся единственное числовое
  свойство той же общей оси («Высота шкафа» у одной позиции = «Высота» у другой).
- Экстрактор: если число у слова-оси подходит к нескольким свойствам, а часть товара не названа, берётся
  единственная общая ось («глубина 40 см» → «Глубина стеллажа», «глубина секции 40 см» → «Глубина секции стеллажа»).
- «Ширина» и «Длина» не отождествляются: это разные слова-оси, у шкафов ими называют разное.
- У части позиций размера нет вовсе («Шкаф архивный металлический» без высоты) — там «свойства нет» верно.

Бенчмарк без изменений; тесты `tests/test_dims.py`, `tests/test_catalog_real.py::test_axis_*`, `test_overall_axis_*`.

### D4. Габариты

- Нормализатор: «120 на 60 на 75», «120 см на 60 см», «120 см x 60 см» → «120 x 60 x 75» (только «на» между
  числами — «стол на 4 ножках» не трогается).
- Экстрактор (`_dimensions`): 2–3 числа через «x» — один признак «габариты» (числа, единицы; единица последнего
  числа применяется к числам без своей), подпись «ДхШхВ» / «ШхГхВ» задаёт оси, «в упаковке …» — размеры упаковки,
  в подборе не участвуют. Числа габаритов больше не уходят по одному в случайные свойства.
- Движок (`dims.resolve`): общие оси типа (D3) → все раскладки чисел по осям (для числа без единицы — мм, см, м);
  раскладка допустима, если каждое число подходит хотя бы одной позиции по КТРУ; диаметр не сочетается с длиной,
  шириной и глубиной. Правдоподобие — произведение долей моделей выгрузок со значением в пределах ±10 % по
  каждой оси; общепринятый порядок записи (высота последней, впереди длина или ширина) — ×3; подпись «ДхШхВ»
  отображается на оси типа (у стеллажа без «длины» Д — ширина, Ш — глубина).
- Вопрос (`kind="dims"`): если лучшая раскладка правдоподобнее второй в 5 раз и более — «верно ли, что это …?»
  с ней первой и альтернативами ниже, иначе «что есть что?» (до 4 вариантов). Вариант ответа несёт три ответа
  сразу (`QuestionOption.answers`); пока ответа нет, габариты неоднозначны и не участвуют в подборе (решение 3).
- У типа меньше общих осей, чем чисел («Стол письменный» — только толщины; «сверло 6х100») — «габариты на выбор
  кода не влияют», без привязки к случайному свойству.
- Одиночная длина без названия («стол 120 см») не бывает толщиной. Первая версия правила исключала и размеры
  частей — на реальных названиях это ломало «сверло по дереву 12 мм» (стало «длина», а это диаметр),
  «футболка 164 см» (рост), «клей-пистолет 7 мм» (диаметр стержня); правило сужено до толщины.

Пробы (реальный каталог, `reports/exp/d4c.txt`):

| Запрос | Первый вариант вопроса |
| --- | --- |
| шкаф для одежды металлический 800х500х1800 мм | одна правдоподобная: длина 800, глубина 500, высота 1800 мм |
| стеллаж 2000х1000х400 мм | одна правдоподобная: высота 2000, ширина 1000, глубина 400 мм |
| стеллаж ДхШхВ 100х40х200 см | по подписи: ширина 100, глубина 40, высота 200 см |
| стол обеденный 120 на 80 на 75 см | длина 120, ширина 80, высота 75 см (ответ → три характеристики, все подходят по КТРУ) |
| шкаф для одежды 80x50x180 (без единицы) | ширина 80, глубина 50, высота 180 см |
| стол письменный в упаковке 120х60х10 см | размеры упаковки, в подборе не участвуют |

На 600 реальных названиях выгрузок: 4 новых автокода («Шкаф деревянный для документов 720х450х900 мм»,
«Стул пластиковый 430х410х480 мм» …) — раньше их блокировало абсурдное «750 мм → толщина?». Проверено вручную:
у каждого единственная конечная позиция (вторая — укрупнённая), наименование совпадает.

### D5. Дискретный диапазон

«Размер 48-50» у свойства со значениями-числами («Российский размер»: 44, 46, 48 …) — подходит, если хотя бы одно
значение позиции внутри диапазона («подходят значения КТРУ 48, 50»), как и для ступеней (решение 1). На реальных
названиях одежды размер теперь привязан ещё в 7 случаях («размер 48-50/158-164»).

### Итог шагов D1–D5

Бенчмарк и стресс-набор — без изменений по кейсам на каждом шаге (диапазонов и габаритов в них почти нет);
поведение закреплено тестами `tests/test_engine.py`, `tests/test_text_processing.py`, `tests/test_dims.py`,
`tests/test_catalog_real.py`. Режим `KTRU_MORPH=snowball` — те же 15 известных падений тестов оркестратора.

Не сделано: «A×B» у инструментов (диаметр × длина сверла) — только пометка «на код не влияют»; разные единицы
внутри габаритов («1,2 м x 60 см») разбираются, но порядок осей при смешанных единицах отдельно не проверялся.
