# Эксперименты 10.10.2026: зависимость от словарей и проверка гипотез

Цель: ядро должно оставаться лёгким и объяснимым, но надёжно ловить проблемы данных из условия — опечатки,
недостаточность и переизбыток данных. Отдельный вопрос: насколько решение держится на словарях.

Все прогоны — на реальном снимке `nsiKTRUNew_all_actual_20261003020003` (дата применимости 09.10.2026),
ядро без моделей (`ktru:core`), Windows 11, Python 3.12. Каждая гипотеза проверялась на всех наборах сразу,
изменения по кейсам сравнивались построчно (`experiments/diff.py`). Принятые гипотезы закоммичены по одной
в ветку `matvey_develop`, отвергнутые откачены.

| реальные наименования СТЕ (`experiments/ste_sample.py`) | 600 (по 200 на файл) | живые формулировки поставщиков из `Примеры выгрузок/`; эталона кода нет, поэтому меряем распознавание типа, привязку признаков и **вручную проверяем каждый автоматический код** |

Ограничения. Стресс-набор и синтетика сгенерированы из каталога — это не независимая оценка живых запросов.
Ручную проверку автокодов на СТЕ делал разработчик, без второй разметки. Числа по СТЕ — доли,
а не точность: что из «тип не распознан» правильно, видно только по ручному разбору.

## Насколько решение зависит от словарей

### Аблации (до исправлений, по одному ресурсу)

| Отключено | Что изменилось |
| --- | --- |
| алиасы типов (`aliases.json`, 10 записей) | manual_dev: −1 автокод |
| алиасы значений (`value_aliases.json`, 5) | behaviour, manual_dev, holdout: по −1 автокоду |
| правила правдоподобия | behaviour: −1 кейс (нет предупреждения «45 м») |
| части товара (`components.json`, 44 слова) | стресс **лучше**: +5 автокодов, полнота признаков 0,926 → 0,95 («полотно» пилы ломало «трикотажное полотно») |
| исправление опечаток по словарю каталога | синтетика: 134 → 124 автокода; стресс: полнота признаков 0,926 → 0,788, неверных автокодов 3 → 4 |
| допуск одной правки в леммах | несущественно |
| всё вместе | стресс: полнота признаков 0,737; manual_dev: pass 0,929 |

### Словарь морфологии (pymorphy3) против бесловарного стеммера

Каталог переимпортирован с каждым вариантом нормализации словоформ.

| Вариант | Бенчмарк (pass, автокоды) | Стресс: полнота признаков | Неверные автокоды | СТЕ «тип не распознан» (одежда / мебель / инстр.) |

### Выводы

1. **Ручные словари почти не нужны для точности.** Четыре ручных ресурса вместе дают ±1–2 автокода
   на ручных наборах. Один из них (части товара) был вреден, пока не исправили правило (H2).
   Их роль заменяют структурные правила — составные слова (H4), предлоги (H6).
2. **Словарь морфологии не обязателен.** Бесловарный стеммер Snowball на всех наборах держит тот же
   результат без неверных кодов и немного лучше распознаёт тип на реальном тексте. Он оставлен опцией
   `KTRU_MORPH=snowball`: значение по умолчанию (pymorphy) решает команда. Без словаря нельзя отличить
   настоящее слово от опечатки («стол» при словаре каталога без «стол» исправится в «стул»). Это закрыто тем,
   что словарь опечаток строится из каталога, но тест на «настоящее слово» в этом режиме пропускается.
3. **Настоящая зависимость — от формулировок самого каталога.** Значения и типы сопоставляются со словами КТРУ.
   Это правильно, потому что КТРУ — источник истины. Но на реальных названиях поставщиков тип не находится у 40 %
   одежды и инструментов. Ручной разбор нераспознанных:
   - **законные отказы** (типа нет в снимке MVP): обувь, сумки, бельё, перфораторы, отвёртки, шпатели, рулетки, комоды;
   - **составные слова** — исправлено (H4);
   - **синонимы** («кофта», «худи», «УШМ») — без алиасов или семантической модели не решаются.
4. **Самый ценный «словарь» — словарь опечаток из слов каталога.** Без него синтетика теряет 10 автокодов,
   а стресс — треть найденных признаков.

## Принятые гипотезы

| № | Что сделано | Результат |
| --- | --- | --- |
| H1 | значение с неполным совпадением слов не опирается на слова наименования; окно для длинных значений; более полное значение поглощает вложенное | **стресс: неверных автокодов 3 → 0**, pass 0,967 → 0,998; синтетика: запрещённых автокодов 6 → 0 («перчатки … для защиты от внешних воздействий» получали код по словам наименования) |
| H2 | слово полностью найденного значения не указывает на часть товара | стресс: +5 автокодов, полнота признаков 0,936 → 0,96 |
| H4 | тип по составу слова: дефис («дрель-шуруповерт»), сложные слова в обе стороны («лобзик электрический» ↔ «Электролобзик»); несколько типов в слове — подтверждает пользователь | СТЕ: «тип не распознан» — инструменты 45,5 → 38 %, мебель 15 → 12,5 % |
| H5 | одно наименование в области подтверждает тип, только если описание его подкрепляет; иначе — вопрос-подтверждение | СТЕ: из 23 автокодов на 6 теперь вопрос; минимум 3 из них были неверными («Комбинезон рабочий» → «Комбинезон гигиенический для посетителей», «Очки защитные» → «Очки для защиты от радиации») |
| H6 | слово после предлога не становится типом | СТЕ: «подставка для паяльника», «бита для шуруповерта», «отвертка … с набором бит» больше не получают чужой тип |
| H7 | из равноудалённых исправлений опечатки выбирается единственное, являющееся типом; неоднозначная опечатка блокирует код, только если её вариант — слово области | стресс: pass 0,998 → 1,0 («куркта» → «куртка», а не «курка») |
| — | режим `KTRU_MORPH=snowball` | см. таблицу выше |
| H10 | **переизбыток данных**: несовместимые значения одного свойства → `conflict` с вопросом; все упоминания логических свойств; привязка чисел: занятые слова, счётные/измеряемые свойства, габариты | стресс, вариант `dup` (67): код до правки выдавался в 27 случаях, после — 0; СТЕ: убрано 9 ложных признаков («размер 54 рост 176» → «Рост=54», «900х400» → «Количество полок=900», «с 6 табуретками» → тип табурет) |
| H11 | обозначение размера одежды: «р.66», «р-р 50», «размер 48/170» (только размеры до 74: обхват груди начинается от 76) | СТЕ: размер привязан ещё примерно в 20 наименованиях одежды; новый автокод «Платье женское р.62» |
| H12 | явно заданное свойство не получает второе значение из слов наименования | синтетика: pass 0,995 → 1,0 |

## Отвергнутые гипотезы

| № | Идея | Почему отвергнута |
| --- | --- | --- |
| H8 | проверять значение у каждого кандидата по словам описания, а не по выбранному тексту значения (разная запись одного значения в соседних семействах) | стресс: pass 1,0 → 0,949 (43 кейса хуже). У различающих свойств одно значение на позицию, поэтому любое совпавшее слово «уникально» и подходит («Стол для переговоров» ≈ «Секция стола для переговоров»). Требование полного совпадения не решает исходный пример |
| H9 | словообразовательное совпадение: общая основа ≥ 6 букв и ≥ 80 % слова | не заменяет алиасы значений («сетевой» ≠ «сети»), полнота признаков на стрессе 0,966 → 0,943, holdout −1 |
| — | усечение до 5 букв вместо лемматизации | 6 неверных автокодов на стрессе |

## Что дальше

1. **Синонимы типов** («кофта», «худи», «УШМ», «перфоратор» как поиск по ОКПД2). Нужен либо список
   проверенных алиасов от команды, либо семантический слой (rubert-tiny2 уже есть за флагом, его выигрыш на этих
   данных не измерен).
2. **Разметка 100–200 реальных СТЕ с кодом КТРУ.** Без неё точность на живом вводе можно оценить только
   ручной проверкой автокодов, как здесь.
3. **Выбор режима морфологии по умолчанию:** snowball проще и быстрее при равном качестве.
   Но тесты оркестратора (заглушки моделей) написаны под леммы pymorphy, их нужно адаптировать.

## Как воспроизвести

```bash
python -m experiments.stress                                  # стресс-набор → experiments/suites/stress.jsonl
python -m experiments.run_exp --ablate none --out reports/exp/base.json
python -m experiments.run_exp --ablate typos,value_alias --out reports/exp/x.json   # аблации
python -m experiments.morph_variant --stemmer snowball --out reports/exp/sb.json     # бесловарный режим
python -m experiments.ste_sample && python -m experiments.ste_run --out reports/exp/ste   # реальные СТЕ
python -m experiments.diff A.json B.json stress OUT.txt       # сравнение по кейсам
```
