## Подробно

### E1. Отрицание значения → неверный автокод (P0, функциональность, распознавание ошибок)

Самая частая причина неверных автокодов на обычных запросах. На dev `natural` это 7 из 9 неверных автокодов,
оставшиеся 2 — E6. На test `natural` неверных автокодов 5, но сами кейсы скрыты (заморозка).
Повторяется в `invariance`, `monotonicity`, `typos_human`, `procurement_noise`, `lazy_user` и `injection`.
В `injection` код из инструкции не подхватывается: неверный код там появляется из-за того же отрицания.

| Запрос | Выдано | Эталон |
|---|---|---|
| «…ветровка, для мальчика, тип ткани — смесовая, **утеплитель отсутствует**, ростом 62 см» | `14.13.10.000-00000021` | `…-00000020` |
| «Нужен диван прямой, количеством посадочных мест 4 шт **механизм раскладывания отсутствует** тип каркаса деревянный» | `31.09.12.110-00000005` | `…-00000003` |
| «Нужна женская куртка зимняя из кожи, **кожа не натуральная**, тип утеплителя искусственный утеплитель, размер 44» | `14.11.10.000-00000003` | `…-00000002` |
| «Мужское пальто нагольное (дубленка), **кожа не натуральная**, размер 48 и **без натурального меха**» | `14.20.10.350-00000004` | `…-00000003` |
| «Женское пальто зимнее с верхом из меха, размер 68, **мех не натуральная**» | `14.20.10.000-00000014` | `…-00000013` |
| «стула на деревянном каркасе сидение из дерева, **мягкое сидение отсутствует**, без мягкой спинки» | `31.01.12.160-00000002` | `…-00000001` |

Ожидается: отрицание даёт «Нет» / «отсутствует» для своего свойства. Если не удаётся однозначно связать
отрицание со свойством, нужен вопрос, а не код.
Действие: разобрать эти кейсы (`python -m benchmark.run --suites benchmark/independent/suites/natural.jsonl --split dev`)
и починить привязку отрицания к свойству в `nlp/extract.py`. Для «X отсутствует» после названия свойства
посмотреть, как это сделано в ветке `Lenaz` (коммит `42a16ef`, H3). У `Lenaz` на test 1 неверный автокод против 5.

### E2. «больше / меньше N» за пределами каталога → автокод (P0)

`lazy_numbers`: 59 неверных автокодов из 1173 (`forbidden_auto_violations` 58).

- «пальто зимнее детское…, для мальчика, **рост больше 206 см**» → `matched 14.13.10.000-00000009`.
  В каталоге нет позиции выше 206 см, кода быть не должно.
- «…**рост меньше 56 см**» → тот же код.
- «пижама детская, для девочки, **рост меньше 56 см**» → `matched 14.14.10.000-00000018`.
- «рост больше 104, но меньше 158» → `conflict`, хотя подходящая позиция есть.

Действие: строгие `>` / `<` и двусторонние интервалы в извлечении и в `validate.py` (луч и диапазон
пересекаются только при непустом пересечении с учётом строгости).
Проверка: `--suites benchmark/metamorphic/suites/lazy_numbers.jsonl`.

### E3. Несколько товаров в одном запросе → автокод (P0)

`multi_item`: 26 автокодов из 60. Примеры:

- «1) …халата операционного… 2) …стула на деревянном каркасе…» → код халата;
- «…полупальто… , а также носок-прокладка…» → код носка;
- «женская футболка… \n требуется реноватор…» → код футболки.

Ожидается: «в запросе несколько товаров» и предложение разделить, кода нет.
Действие: детектор нескольких товаров — два и больше типа из реестра, разделители `;`, «а также», нумерация,
перенос строки. Статус `conflict` или `manual_choice` с понятным сообщением.

### E4. Повтор категориального свойства с разными значениями (P0)

`contradictions` test: код не выдан в 94,1% кейсов, то есть 6 из 102 получили код; на dev неверных автокодов 20.

- «Джинсы детские половой признак: Для мальчика, половой признак: Для девочки, ростом 860 миллиметров» → код;
- «куртка зимняя… назначение: Мужская, назначение: Женская» → код;
- «Мужская сорочка материал изделия: Ткань, материал изделия: Трикотажное полотно» → код.

Для чисел это уже работает: «длина 18 см, длина 25 см» → `conflict`.
Действие: та же проверка `contradictory_values` для качественных значений одного свойства.

### U1. Ошибки спрятаны (P0, распознавание ошибок 12 баллов, интерфейс)

`frontend/src/components.jsx:134` — все `issues` (и `error`, и `warning`) показываются одинаково, в свёрнутом
`<details>` «Проверка описания N». Пример: «дрель ручная электрическая мощность 220 В». API возвращает ошибку
`dimension_mismatch` («указано «В», в КТРУ — «Вт». Это разные физические величины»), а на экране у поля
«Мощность» стоит «220 В» без красной метки.

Действие: ошибки `error` показывать раскрытыми и красным, рядом с полем (`feature_id` / `property_name` есть в issue).
`implausible_value` и `suspect_scale` («45 м — возможно, 45 см») — заметным предупреждением с кнопкой
«исправить на 45 см».

### U2. Пустая вкладка «Товары СТЕ» (P0 для демо)

В режиме по умолчанию (`RECOGNITION_MODE=rules`) `ste_results` не заполняется, и вкладка всегда показывает 0.
Заполняется только в `hybrid` с `data/ste.sqlite` и Qwen (`LLM_MODE=always`, нужен GPU).
Действие: решить, на каком режиме идёт демо. Без GPU — скрывать вкладку или делать активной вкладку
«Позиции КТРУ». Режим и машину демо зафиксировать в README.

### E5. Ошибка в записи числа принимается молча (P1)

`number_errors`: 30 автокодов из 160, хотя по набору автокод запрещён. Примеры: «мощностью **0475** ватт»,
«длиной **016** см», «свинцовым эквивалентом **01** мм», «высотой **0400** мм».
Действие: ведущий ноль у целого, буква в числе («18о»), двойной разделитель («1,,8»), разбитые разряды («1 80»)
→ предупреждение и вопрос «вы имели в виду 475 Вт?», без автокода.

### E6. Значения со скобками (P1)

«одежда специальная для защиты от пониженных температур **класс защиты одежды — 1 (II-I климатические пояса)**,
женский, полукомбинезон» → `14.12.30.160-00000377`, эталон `…-00000429`.
Встречается в `injection`, `invariance` и `lazy_user`. Действие: сопоставление значения со скобочным уточнением
с допустимыми значениями КТРУ.

### E7. Свойство не привязывается (P1)

- «стул на металлическом каркасе … высота сиденья 45 см» → `unknown_property`: «у позиций этого типа нет свойства
  «сиденья» подходящей размерности». Число теряется. Нужно проверить название характеристики в КТРУ и добавить синоним.
- «куртка мужская утепленная материал верха: картон» → всё до двоеточия считается названием свойства:
  «нет свойства с таким названием: куртка мужская утепленная материал верха».
- «стул на металлическом каркасе, материал каркаса деревянный» → противоречие не найдено, «материал» не распознан.

### E8. Бесполезные вопросы (P1, функциональность — «конкретные шаги»)

`useless_question_rate` — доля вопросов, после которых список не сузился:

| natural test | lazy_numbers | stress | synthetic | manual_dev |
|---|---|---|---|---|
| 0,578 | 0,908 | 0,894 | 0,671 | 0,889 |

Часто вопрос задаётся про обязательное свойство, когда позиция уже одна («позиция определена, но обязательное
свойство не заполнено»). Для правила `matched` это верно, но выглядит как лишний шаг.
Действие: в интерфейсе различать «уточняем, чтобы сузить» и «дозаполняем обязательные поля для итоговой позиции».
Метрика — по ответу на первый вид вопросов.
