Основа — анализ вариантов `docs/LEVELS_ANALYSIS.md`. Здесь — что из него берём, что меняем по фактам данных
и в каком порядке реализуем.

## Принципы (без изменений из анализа)

- Уровень 1 (КТРУ) — единственный судья совместимости и кода. Уровни 2 и 3 его не читают и не меняют.
- Уровень 2 относится к признаку, а не к паре «признак × позиция», поэтому физически не может отбирать позиции.
- Уровень 3 только предлагает исправление («Заменить» / «Оставить»); принятое исправление — новый ввод,
  который заново проходит уровень 1.
- Без артефакта статистики сервис работает как сейчас. Тест неизменности: кандидаты, статусы и код
  совпадают с артефактом и без него на всех наборах.
- Формулировки — «не встречается у N моделей», а не «так не бывает».

## Журнал

### A1. Причина unknown (10.10.2026, `323ebbc`)

- `PropertyCheck.unknown_reason`: `not_specified`, `ambiguous`, `property_absent`, `not_comparable`, `unconfirmed`.
- `ambiguous` — новое: обязательное свойство не привязано, но в описании есть слово, подходящее к нескольким
  свойствам области, и одно из них — это («мужская» → «Половой признак» или «Назначение»). Раньше такая
  проверка выглядела как «не заполнено».
- Карточка: проверки по группам (совпадает / не подходит / уточните / не удалось проверить / не указано).
- Замер: бенчмарк и стресс-набор без изменений по кейсам (`experiments/diff.py`).

### A2. Уровень 3 по интервалам КТРУ (10.10.2026)

Модуль `ktru_assist/suspicious.py`, поле ответа `suggestions`, предупреждения `suspect_*` в `issues`.

Правила:
- `scale` — значение не подходит **ни одной** позиции области, у которой есть свойство. Перебираются та же цифра
  в другой единице той же размерности (без дюймов, км, дм, т, мг, м³, кВ) и ×10 / ÷10 в той же единице.
  Варианты с одной физической величиной склеиваются («170 см» = «1700 мм»). Исправление предлагается, только
  если осталась одна величина; иначе варианты перечисляются без готового исправления.
- `unit_missing` — число без единицы; показывается, только если КТРУ различает единицы (подходят не все).
- `placeholder` — 0 у положительной физической величины.

Интерфейс: карточка «Замечания» (в упрощённом интерфейсе замечания ядра не выводились совсем).
«Заменить» правит фрагмент описания по `replace_span` — это новый ввод, он заново проходит уровень 1.
«Оставить» кладёт `id` предложения в `confirmed`.

Синтетика `experiments/l3_synth.py` (синтетический и стресс-наборы, 463 числовых признака с единицей):

| Порча | Случаев | Видно по КТРУ (потолок) | Найдено из видимых | Исправление верное | Без исправления (неоднозначно) |
| --- | ---: | ---: | ---: | ---: | ---: |
| другая единица (мм↔см↔м, г↔кг, Вт↔кВт, мА·ч↔А·ч, мл↔л) | 727 | 30 % | 100 % | 262 из 262 | 11 |
| лишний ноль (×10) | 463 | 24 % | 100 % | 141 из 141 | 0 |
| пропущенный ноль (÷10) | 463 | 38 % | 100 % | 195 из 195 | 15 |
| ложные тревоги на неиспорченных текстах | 463 признака | — | 0 | — | — |

Выводы:
- Где КТРУ видит ошибку, правило её находит, и исправление верное. Первая версия выбирала «другую единицу»
  раньше «лишнего нуля» и ошибалась («обхват 9,8 см» → «9,8 м» вместо «98 см»); после склейки по физической
  величине и отказа от выбора при нескольких величинах неверных исправлений нет.
- Потолок 24–38 %: у большинства свойств интервалы КТРУ широкие (длина пассатижей «180 см» допустима).
  Остальное — задача уровня 2 (статистика выгрузок).
- Испорченные значения, которые КТРУ допускает, иногда дают автоматический код; неверных кодов среди них нет
  (эталон тот же), но значение в характеристиках останется ошибочным — тоже задача уровня 2.
- Уровень 1 не изменился: бенчмарк и стресс без изменений по кейсам; тест
  `test_level3_does_not_change_level1`.
- Задержка: с уровнем 3 p50 70–81 мс, без него 76 мс на той же машине — в пределах шума. **Открытый вопрос:**
  в замере 10.10 до слияния с `aydar` p50 был 41 мс; причина роста не выяснена (машина или изменения ветки).

### B1. Сборка статистики выгрузок (10.10.2026)

`python -m ktru_assist.catalog.ste_stats` → `data/ste_stats.sqlite` (56 МБ, 18 минут на ноутбуке; большая база
выгрузок не строится). Отчёт сборки — `reports/ste_stats_report.json`.

| | Значение |
| --- | ---: |
| Карточек | 299 986 |
| Тип определён (тем же реестром, что запросы) | 204 262 (68 %) |
| Тип не найден | 93 639 |
| Тип из другого направления, чем файл | 2 084 |
| Типов | 820 |

Не привязаны чаще всего: «ушм» 4 648, «ботинки» 4 177, «сапоги» 3 268, «перфоратор» 2 658, «рюкзак» 2 147,
«полуботинки», «полукомбинезон», «отвертка», «электроды», «кроссовки». Обувь, рюкзаки, перфораторы — законные
отказы (типа нет в снимке MVP); «ушм», «электропила», «отвертка» — синонимы, которые закрываются только алиасами.

Решения:
- ключ типа — отсортированные главные слова («дрель|шуруповерт»), тот же код, что для запроса;
- единица счёта — модель (производитель + модель), значение модели — большинство её карточек;
- в статистику идут только числа с распознанной единицей (или единицей в скобках названия, или счётные
  «количество …»); диапазоны и габариты «38,5x20x22» в первой версии не оцениваются;
- зоны считаются при загрузке по таблице частот (`ste_stats.zones_from_freq`): логарифмическая шкала,
  10 интервалов на порядок, интервал «занят» при ≥ 0,5 % моделей, зона типична при ≥ 5 %. Первая версия
  (любой занятый интервал) склеивала ширину столов в одну зону «5,2 см – 18 м».

### B2. Сопоставление названий — отложено

`experiments/prop_coverage.py`: у типов с поддержкой не ниже N1 свойство КТРУ находится в выгрузках по точному
названию в 800 из 1016 случаев (79 %). Среди ненайденных — редкие свойства («Наличие встроенной раковины») и
одна заметная пара «Российский размер» (КТРУ) / «размер» (выгрузки). Автоматическое сопоставление с запретами
сейчас не окупается; кандидаты для ручных пар — в `reports/exp/prop_coverage.txt` (не в git).

### B3. Уровень 2 (`ktru_assist/empirical.py`, поле ответа `empirical`)

- Статусы `typical` / `rare` / `unseen` / `not_assessed` с причиной; вердикт у признака, не у позиции.
- Пороги: N1 = 30 моделей и 3 производителя (ниже молчим), N2 = 60 и 5 (ниже не говорим «не встречается»).
  Стартовые значения из анализа, калибровка — по оценке на отложенных производителях.
- **Текст:** «не встречается» не утверждаем. На чистых кейсах бенчмарка первая версия давала `unseen` у 186 текстовых
  признаков: наборы «металлический и деревянный» сравнивались целиком, «мужская» ≠ «мужской», «от аккумуляторных
  батарей» ≠ «от аккумулятора», «Тип» молотка в выгрузках = «молоток слесарный». Теперь сравнение по леммам и по
  каждому значению набора, не найдено — `not_assessed: text_not_found`. Уровень 1 и так проверяет текст по закрытому
  списку КТРУ.
- **Числа:** на чистых кейсах бенчмарка `unseen` у 30 из 289 числовых признаков — крайние значения КТРУ, которых
  нет у реальных товаров (рост 56–74 см у детской одежды). Это правда, а не ложная тревога; доля ложных — по
  оценке на отложенных производителях.
- **Свойства вне КТРУ** (`presence`): признак `unknown_property` с названием из текста. Если у этого типа в
  выгрузках есть свойство с теми же леммами — «на выбор кода не влияет, обычное свойство таких товаров (у N из M
  моделей)» и оценка значения; если нет ни у одной модели типа, но есть у других — подсказка «встречается у …».
  Общие свойства (у 10 и более типов: цвет, вес) и реквизиты карточки (страна, производитель) «чужими» не называются:
  первая версия писала «страна происхождения не встречается у стульев, проверьте товар».
- Без файла или при другом снимке КТРУ — `not_assessed` с причиной (`no_artifact`, `stale_snapshot`).

### B4. Уровень 3 по выгрузкам

`scale` срабатывает и тогда, когда КТРУ значение допускает, но в выгрузках оно не встречается: предлагается
вариант (другая единица, ×10, ÷10), который обычен по выгрузкам и не противоречит КТРУ. Если по КТРУ подходят
несколько вариантов, выгрузки выбирают единственный обычный. Счётные свойства по выгрузкам не правятся
(«фреза дисковая, 40 зубьев» — реальное значение, хотя у большинства фрез в выгрузках 2–6 зубьев).

Синтетика `experiments/l3_synth.py` (те же 463 числовых признака):

| Порча | Найдено: только КТРУ | Найдено: КТРУ + выгрузки | Неверных исправлений |
| --- | ---: | ---: | ---: |
| другая единица | 30 % | 66 % | 5 из 465 |
| лишний ноль (×10) | 24 % | 50 % | 0 из 232 |
| пропущенный ноль (÷10) | 38 % | 61 % | 0 из 276 |
| ложные тревоги на неиспорченных | 0 | 0 | — |

Неверные исправления — снова подтипы: «диаметр фрезы 25 м» → предложено «25 мм» (в выгрузках концевые фрезы),
исходно было «25 см» (дисковая).

Проверки: уровень 1 без изменений по кейсам на всех наборах; тесты `tests/test_empirical.py` (статусы, перевод
единиц, леммы, наборы, поддержка, отсутствие и устаревание артефакта, свойства вне КТРУ).

Живые примеры (полный каталог):
- «пассатижи слесарные длина 180 см» — код выдан (КТРУ допускает), замечание: в выгрузках у 269 моделей
  11,5–30 см, возможно, 180 мм;
- «шуруповерт аккумуляторный крутящий момент 350 Н·м» — возможно, 35 Н·м;
- «дрель ударная мощность 7 кВт» — обычно 0,32–1,2 кВт, возможно, 0,7 кВт;
- «стул на металлическом каркасе мощность 500 Вт» — у стульев не встречается, встречается у пил, лобзиков, шлифмашин;
- «стол письменный ширина 60 см» — ширины нет в КТРУ столов, на код не влияет, обычное значение по выгрузкам.
