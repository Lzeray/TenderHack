# Разбор описания: ошибки и ввод «ключ: значение»

Постановка пользователя (10.10.2026): «стол деревянный столешница лдсп» — тип стол, материал (каркас) дерево,
столешница ЛДСП. Система задавала два лишних вопроса, а после выбора варианта плашка выбора оставалась.
Предложение: разобранная строка после Enter превращается в скрытую строку «тип; ключ: значение; …», так же —
при добавлении характеристики; в видимой строке ввода исправляется только орфография.

## Журнал

### P1. Часть товара и прилагательное (extractor 2.4)

Было: «стол деревянный столешница лдсп» → «стол деревянный столешница» — неоднозначно (значение «Стол» с частью
«столешница»), «лдсп» — неоднозначно (каркас / столешница). Причины:
- слову типа («стол» → «Вид товара: Стол») приписывалась ближайшая часть товара («столешница» в двух словах);
- «столешница» после этого была занята, и «лдсп» оставалось без части.

Стало: слово типа часть товара не получает; прилагательное-значение относится к части, только если согласуется с ней
по роду, числу и падежу («деревянная столешница» — да; «стол деревянный столешница» — нет, «деревянный» про
стол). Существительные-значения («лдсп») не проверяются. Результат: «Вид товара: Стол», «Тип каркаса: Деревянный»,
«Вид материала столешницы: ЛДСП», вопросов о привязке нет.

### P2. Выбор варианта не снимал неоднозначность (engine 2.10)

Интерфейс отправляет ручную правку «свойство = значение варианта». Правка привязывалась, но признак из текста
оставался `ambiguous`: в момент сравнения у него запись из текста («лдсп»), к написанию КТРУ («ЛДСП») она
приводится позже, а сравнение было с учётом регистра. Теперь — без регистра и с значением варианта; признак
получает статус `overridden`, плашка выбора не показывается.

### P3. «свойство: нет» читалось как отрицание (extractor 2.4)

«наличие мягкого сидения: нет» давало `ne Нет` (то есть «есть»). Отрицание в конструкции «характеристика:
значение» — только если после «не / нет / без» есть само значение («материал: не лдсп»).

Проверка P1–P3: pytest 262; стенд полноты (`reports/exp/kr_p2.json`) — ни один из 626 ответов не изменился;
бенчмарк — те же цифры, `dialog_resolved` synthetic 0,985 → 0,992; наборы ветки — изменений по кейсам нет.
