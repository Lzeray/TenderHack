# Одно свойство — разные записи в КТРУ

Сообщение пользователя (11.10.2026): на «стул» в «Осталось заполнить» две строки «Наличие мягкого сидения» — у одних
позиций выбор «Да/Нет», у других только «Да».

## Причина

Это две записи: «Наличие мягкого с**и**дения» (8 позиций) и «Наличие мягкого сид**е**нья» (3 позиции, «Секция стульев
многоместная»). Ключ характеристики был названием по словам, поэтому написания считались разными свойствами: две
строки в «Осталось заполнить», вопрос по одному написанию не сужал позиции с другим, значение пользователя
привязывалось к одной группе, а позиции с другим написанием оставались непроверенными.

## Где ещё (`experiments/property_variants.py`, `reports/exp/property_variants.json`, все 137 типов)

Названия, которые на деле одно свойство (новый ключ склеивает ровно их, ни одна пара не встречается в одной позиции):

| Написания | Типы |
| --- | --- |
| Наличие мягкого сидения / сиденья | стул |
| Вид материала сидения / сиденья | стул |
| Натуральная мех / Натуральный мех | куртка, пальто |
| Наличие подвеса / подвесов для скамьи | стол |
| Наличие полки / полок | стол |
| Наличие ящика / ящиков | стол |

Похожие по написанию, но разные свойства (не склеиваются): «Количество закрытых / открытых секций», «Форма бойка /
носка», «Максимальная глубина пропила под углом 45 / 90», «Вид X / Тип X» — в одних позициях встречаются вместе.

Категориальные значения одного свойства у разных позиций: «Женская / Женский», «Мужская / Мужской» (Половая
принадлежность, спецодежда), «Прямая / Прямой», «Угловая / Угловой» (Тип конструкции, шкафы). Фильтрация их не
различала и раньше (значения сравниваются по леммам), но в вопросе и в списке допустимых значений были два варианта.

## Исправление

- `text.property_key`: ключ характеристики — основы лемм слов названия. `Prop.norm_name`, группы разбора, поиск
  свойства у позиции, ручной ввод, ответы, список обязательных — по нему (extractor 2.9, validator 1.10,
  engine 2.17, clarifier 2.2).
- Название группы и строки «Осталось заполнить» — самое частое написание («Натуральный мех», а не «Натуральная мех»).
- Варианты ответа и допустимые значения в списке обязательных — по леммам: «Прямой / Угловой» вместо «Прямая / Прямой
  / Угловая / Угловой».

Проверка: «стул» — одна строка «Наличие мягкого сидения» на 11 позиций; «стул, наличие мягкого сиденья: да» отбирает и
«Секцию стульев»; pytest 257; стенды полноты, скрытой строки, перебора вопросов, `natural` и 35 сценариев в браузере —
без изменений.

## Синонимы по смыслу — не исправлено, нужно решение (`experiments/property_synonyms.py`)

Разные названия одного понятия, которые никогда не встречаются в одной позиции и совпадают по значениям:

| Свойства | Типы |
| --- | --- |
| Пол / Половая принадлежность / Половозрастная группа / Половой признак | одежда (80 / 352 / 1), брюки, перчатки, рукавицы |
| Тип ткани / Тип ткани/трикотажного полотна | сорочка, халат |
| Тип напольной опоры / Тип основания | шкаф |
| Вид материала обивки / Тип обивки | банкетка |
| Конфигурация стола / Тип конструкции стола (частично) | стол |
| Тип / Тип фасада | шкаф |

Ложные кандидаты того же поиска: «Класс воздухопроницаемости / Класс одежды в зависимости от площади сигнальных
элементов» (совпадают только числа 1, 2, 3). Склейка по смыслу — решение команды: список пар в файле данных
(как алиасы), с проверкой тестом, что пары не встречаются в одной позиции.
