## Q1. Тип по наименованию КТРУ

- `item_words` (`catalog/repository.py`): позиция относится к типу и по другим словам типа в наименовании, если
  слово не стоит после предлога в своей группе (до запятой, «/», скобки или начала). «Секция стульев многоместная» —
  «стул», «Шкаф для одежды» — не «одежда», «Шаблон для заточки спиральных сверл» — не «сверло».
- «Вид товара» из слова типа совпадает, если слово типа есть в значении («Секция стола» — да, «Гольфы» для «чулок» —
  нет). Такой признак не считается заданной характеристикой: по «Вид товара» можно спросить.
- Сверка после: тот же главный тип 1136 из 1136, плюс 19 разновидностей; «стул» 11 → 14, «стол» 35 → 38,
  «шкаф» 22 → 24. Оставшиеся исключения — другие изделия и «Гольфы» при запросе «чулок» (КТРУ: вид изделия —
  гольфы).

## Q2. Два уточняющих вопроса (`ktru_assist/qplan.py`, `clarify.choose_question` 2.0)

Решения команды: вопросов не больше двух, затем — список характеристик, которые осталось заполнить («Осталось
ввести»); варианта «Не знаю» нет; проверка — полным перебором, а не придуманными строками.

S — совместимые конечные позиции после всего известного (разбор строки, ответы). Кандидаты в вопросы — все не
заданные характеристики и наименование позиции (обычный вопрос, не обязательный первый). Ответ a — допустимое
значение КТРУ; ветка S_a — позиции, допускающие a (для чисел — пересечение интервалов), и позиции без
характеристики (unknown ≠ invalid). Варианты ответа — все значения КТРУ оставшихся позиций, частые в выгрузках —
первыми.

Вероятность ответа: пользователю нужна одна из позиций S (равновероятно); позиция с k значениями даёт каждое с
вероятностью 1/k; позиция без характеристики — любое из встречающихся ∝ w(a), w(a) = 1 + β·доля a среди товаров
этого типа в выгрузках (β = 1: слабая поправка).

Ценность состояния T при оставшемся бюджете b — пара (P(позиция определена), −E log2 |T_конец|):

    b = 0 или |T| ≤ 1:  (1, 0) при |T| = 1, иначе (0, −log2 |T|);
    b > 0:              max_q Σ_a P(a|T)·V(T_a, b − 1)   (сравнение лексикографическое).

Первый вопрос выбирается полным перебором обеих ступеней: для каждого вопроса и каждого ответа — лучший второй
вопрос. Множества — битовые маски, без внешних зависимостей; время — до 1 с на 442 позиции спецодежды. Бюджет в ядре:
2 − число характеристик в ответах; после двух ответов вопросов нет, в сообщении — «дозаполните характеристики из
списка «Осталось ввести»».

Сопутствующее: тип, заданный главным словом, считается подтверждённым, когда ответы сузили выбор до одного
наименования («дрель» → ответы → одна позиция → код; раньше — бесконечные вопросы об обязательных
характеристиках). Для «кресло-качалка» при единственном наименовании области подтверждение по-прежнему нужно.

Проверка — `experiments/question_bruteforce.py`: для каждого стартового запроса (главное слово каждого типа или
наименование каждой позиции) через ядро перебираются все ответы на первый вопрос и для каждого — все ответы на второй.
Позиция определена за k вопросов, если на правдивом пути (её значения) после k ответов выдан её код или совместимой
осталась только она; если у позиции нет спрашиваемой характеристики, берётся худший из вариантов, при которых она
сохраняется. Сравнение — с прежним выбором вопросов на том же ядре (копия с прежним `clarify.py`).

Полный перебор (`experiments/question_bruteforce.py`, старт — главное слово каждого из 134 типов, 1136 позиций,
все ответы на первый и второй вопрос через ядро):

| --- | ---: | ---: | ---: |
| прежний выбор вопросов (то же ядро, `reports/exp`, копия) | 3,6 % | 21,5 % | 44,9 % |

Старт с наименования позиции (272 наименования, 1120 позиций, до правки ответа по названию): прежний 57,7 %,
новый 57,5 %.

Границы (`experiments/question_bounds.py`, старт — главное слово): различимы вообще — 96,2 % позиций; оракул-2
(лучшая пара вопросов под каждую позицию, верхняя граница для любого алгоритма из двух вопросов) — **50,5 %**;
модель планировщика — 48,6 %. Ограничение структурное: «одежда» — 442 позиции под одним словом, оракул выделяет за
два вопроса 12; неразличимые позиции («сверло», «клеймо» — по 2 позиции с одинаковыми характеристиками).

Исправлено по ходу (модель планировщика расходилась с ядром):
- позиция без характеристики, у которой текстового значения нет ни в одной характеристике, ядром исключается
  (`_value_support` из `main`) — модель держала её во всех ветках; теперь как в ядре, а вероятность такой позиции
  — неудача, а не чужая ветка;
- ответ на вопрос нёс код характеристики; после вопроса о наименовании у позиций другого наименования код другой,
  и ответ терялся («пальто»: 4 позиции вместо 2). Теперь ответ несёт ключ-название характеристики.
После этого размеры веток модели и ядра совпали во всех 1040 узлах дерева (обе ступени, все типы).

Не сделано (остановлено по просьбе пользователя): пересчёт границ и перебора по наименованиям после последней правки;
перебор по стартам «тип + одна характеристика». pytest 289.
