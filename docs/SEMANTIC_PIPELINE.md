# Семантический пайплайн без обязательного словаря синонимов

## Состояние

Добавлен экспериментальный режим `RECOGNITION_MODE=semantic`. Он использует существующий `Engine`, `validate`, правила Decimal/размерностей и импорт XML. Исторический режим `rules` оставлен для сравнения и отката.

В новом пути не вызываются распознавание по главному слову, SymSpell, алиасы типов/значений и лемматизация. `pymorphy3` загружается лениво только старым путём. Это проверяется тестом с запрещёнными словарными функциями. Каталог значений КТРУ и словарь единиц ОКЕИ остаются необходимыми источниками проверки.

Это работающая интеграция и первый эксперимент, не подтверждённая готовность к автоматическому распознаванию любых описаний. Реальная Qwen пока пропускает свойства и нарушает требование точных цитат; такие элементы отклоняются и требуют ручного ввода.

## Запуск

Из корня проекта, после импорта `data/ktru.sqlite`:

```bash
.venv/bin/python -m pip install -r requirements-ml.txt
# Скачать закреплённый rubert-tiny2 и Qwen через локальный Ollama:
PYTHON=.venv/bin/python bash tools/fetch_models.sh
# Построить индекс офлайн:
HF_HUB_DISABLE_PROGRESS_BARS=1 .venv/bin/python -m ktru_assist.semantic.catalog_index
# Запустить веб-приложение:
RECOGNITION_MODE=semantic SEMANTIC=1 LLM_MODE=always LLM_TIMEOUT_S=90 \
  HF_HUB_DISABLE_PROGRESS_BARS=1 TRANSFORMERS_VERBOSITY=error \
  .venv/bin/python -m ktru_assist.cli serve --host 127.0.0.1 --port 8000
```

На Linux можно заменить `.venv/bin/python` на нужный интерпретатор. На Windows переменные окружения задаются средствами оболочки. Ollama должен быть запущен отдельно на `127.0.0.1:11434`.

Энкодер: локальный Transformers, CPU, CLS + L2, длина до 128 токенов, 4 CPU-потока. Зависимости ML закреплены в `requirements-ml.txt`. Старый numpy-адаптер сохранён для сравнения.

LLM: `qwen3:4b-instruct-2507-q4_K_M`, `temperature=0`, `seed=0`, контекст 16 384, максимум ответа 2 048 токенов, JSON Schema в Ollama. Runtime изолирован `complete(messages, schema)`; в MVP используется существующий Ollama, vLLM-адаптер не реализован. После смены модели или снимка перезапустить сервис: сеанс закрепляет каталог и digest модели, перед новым инференсом digest проверяется.

Загрузка моделей выполняется явно; сервер не скачивает веса при запросе. Инициализация и загрузка индекса выполняются до приёма HTTP-запросов, отдельно от задержки быстрого пути.

## Процесс в интерфейсе

1. При наборе, после debounce 200 мс, энкодер предлагает до 8 обозначений каталога. Значение debounce можно изменить параметром страницы `?debounce=250`.
2. Предложения не являются подтверждением типа и не сужают область ядра. Пока тип не выбран, область — все активные позиции трёх групп.
   В интерфейсе при этом показывается отдельный список `preview_candidates` по поисковым предложениям, а не весь каталог в алфавитном порядке. Этот список не является доказанной совместимостью.
3. Пользователь подтверждает обозначение из подсказки либо находит его в полном списке. Есть сброс «ни один / другой тип».
4. Enter запускает один логический вызов LLM для подтверждённой области. Без подтверждения типа генерация не запускается.
5. Модель возвращает исходные фрагменты, значения и единицы, операции, ссылки и предложения значений. Сервер устанавливает происхождение, ревизию и статус подтверждения.
6. Неподтверждённые признаки получают `unknown` в проверках кандидатов и не исключают позиции. Пользователь может принять карточку целиком, отдельное предложение, исправить значение либо открыть весь набор допустимых значений.
7. Непривязанный признак сохраняется и сопоставляется с полной схемой для подсказок; привязка выбирается вручную. Отклонение интерпретации сохраняет исходный фрагмент как неопределённый. Явное исключение фрагмента из подбора — отдельное действие.
8. Подтверждение не запускает новую генерацию: сервер повторно валидирует сохранённый ответ и пересчитывает настоящее ядро.
9. При сбое или непригодном разборе доступен явный ручной режим. Он проверяет только введённые пользователем характеристики и сообщает это в ответе. Невалидная модель не превращается в эталон.

Даже пустой валидный ответ модели требует проверки пользователем: он не доказывает отсутствие характеристик в описании. Предпочтения не становятся жёсткими фильтрами после подтверждения.

## Идентификаторы и область

`catalog/scope.py` строит проверяемые обозначения по паре «группа организатора + точное наименование каталога». Членство хранится как полный список кодов позиций; это не кластер эмбеддингов и не онтология типов. Пользователь подтверждает именно обозначение каталога, а не доказанную моделью принадлежность разговорного слова.

Позиции, характеристики и значения имеют ссылки из своих исходных идентификаторов и контекста. Для характеристики используются код и исходное название; одинаковые названия разных кодов не объединяются. Ручные ответы нового пути используют `characteristic:…`, а не неоднозначное название или код. Ядро проверяет исходный код и название у конкретной позиции. Прямой ручной выбор конечной позиции — явное ограничение пользователя, а не доказательство уникальности поискового top-K.

Полный набор активных позиций выбранного обозначения проверяется без `TYPE_FETCH_LIMIT`. `compatible_codes` отдаёт полный набор конечных совместимых кодов отдельно от ограниченной визуальной выдачи. `matched` требует полного подтверждённого охвата, достаточности характеристик и отсутствия блокирующей неопределённости. Черновик не возвращает окончательный код.

## Семантический индекс

`semantic/catalog_index.py` формирует документы из сохранённых полей каталога, строит нормированные матрицы позиций, обозначений, характеристик и значений. Поиск точный, по косинусной близости; ANN пока не нужен.

`data/cache/catalog_*.npz` хранит матрицы и соответствие строк ссылкам. Рядом JSON с документами, версией формата, моделью и снимком. При загрузке проверяются идентификаторы, конечность и L2-норма векторов.

Ранжирование предложений сочетает название (0,8) и справочный документ (0,2). Для маленького энкодера учитываются исходный текст и до четырёх начальных префиксов: длинные числовые суффиксы иначе подавляли название. Это фиксированная поисковая эвристика, не доказательство типа и не откалиброванная вероятность.

Ограничение данных: действующий импорт не сохраняет все описания `nsiDescription`. Система не подменяет отсутствующее описание выдуманным. Родительские ссылки с несовпадающими версиями не используются как доказательство таксономии. Стабильность сущностей между разными снимками отдельно не доказана.

## Проверка извлечения и защита состояния

- Pydantic проверяет всю структуру и запрещает дополнительные поля. Схема constrained output дополнительно ограничивает допустимые ID текущим контекстом.
- Цитата должна быть точной уникальной подстрокой исходного текста, включая регистр. Повторение остаётся неопределённым, смещения не угадываются.
- Значение и единица должны присутствовать в цитате. Число проверяется как отдельный исходный токен и разбирается Decimal: «190» внутри «1190» не принимается.
- ID значения обязан принадлежать указанной характеристике. Обрезанный ответ не применяется.
- Для `in` сохраняется исходный набор; ядро различает полное, отсутствующее и частичное соответствие.
- Обрезанный контекст отмечается; полный набор характеристик остаётся доступным серверу и ручному интерфейсу. Отсутствие в контексте не доказывает отсутствия в каталоге.
- Приоритет ручной правки выше старого ответа на вопрос. Изменение текста сбрасывает ручные поля и подтверждения в UI.
- `/api/revision` регистрирует изменение до debounce. Старые результаты помечаются `stale`, не применяются клиентом; старые ожидающие LLM-задачи пропускаются. Исполняемый инференс может завершиться, но его ответ игнорируется.
- Кэши учитывают текст, данные пользователя, контекст, модели, параметры и версии. Подтверждение интерпретации — не доказательство правильности модели.
- `EVENT_LOG` по умолчанию для нового пути: `data/cache/semantic-events.jsonl`. Журнал содержит вход, выход, контекст, ответ модели, ошибки и время, включая непригодные ответы. Сохранённых фактов достаточно для повторения решения ядром.

Проверки правдоподобия из старого пути не переносятся как универсальные пределы: новые неподтверждённые размеры не вводились. Числа модели в любом случае требуют подтверждения; нормативные диапазоны проверяет ядро.

## Полные варианты и необязательный скорер

`GET /api/catalog/values?type_ref=…&characteristic_ref=…&text=…` возвращает полный закрытый набор и точные ответы для ядра. По умолчанию дополнительный скорер выключен.

`semantic/value_scorer.py` содержит сменный контракт и экспериментальный локальный cross-encoder backend. Включение только явно: `VALUE_SCORER=cross_encoder CROSS_ENCODER_PATH=…`. Веса DiTy не скачивались, выигрыш не измерен; включать как обязательный компонент нельзя. Пороги `VALUE_MIN_SCORE` и `VALUE_MARGIN` находятся вне модели и требуют калибровки на независимых данных. Сбой, неполные оценки и плоская выдача не скрывают исходные варианты; обрезание рекомендаций явно отмечается.

## Тесты и измерения

Из `origin/main` (коммит `153e75d`) перенесены `benchmark/` и `tests/test_benchmark_harness.py`. Удаления тестов в другой ветке не переносились; текущие проверки оркестратора и fixture сохранены. Исходные benchmark-кейсы не менялись.

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m benchmark.run --adapter ktru:core --suites all --repeat 2 --out reports/bench/core.json
RECOGNITION_MODE=semantic SEMANTIC=1 LLM_MODE=always LLM_TIMEOUT_S=90 \
  .venv/bin/python -m eval.catalog_pipeline --full 3 --out reports/catalog_pipeline.json
.venv/bin/python tools/build_annotation_queue.py
```

Общий benchmark: 18 поведенческих, 28 dev, 18 holdout и 984 синтетических случая. Для нового режима есть адаптер `ktru:semantic_catalog`. Старые требования `auto=required` не учитывают обязательное подтверждение новой системы: не переименовывать эталоны под реализацию, измерять диалог и качество предложений отдельно.

На локальном Mac arm64, Python 3.14.3, CPU-энкодер + настоящая Qwen:
- 46 запросов быстрого пути: p50 около 56 мс, p95 около 98 мс; без сети, debounce и отрисовки.
- Нужное обозначение в top-8: 33/37 запросов с известным кодом; не независимая оценка живого трафика.
- Черновых `matched`: 0.
- Три полных разбора по разным группам: примерно 10,4 / 46,4 / 13,7 с. Тип выбирался по эталону в симуляции. Были пропуски и отклонённые цитаты; до конечного кода они автоматически не дошли. Это проверка интеграции, не доказательство качества LLM.
- Ollama сообщил около 5,11 ГБ GPU-памяти с контекстом 16k; энкодер работал на CPU. На macOS это unified memory, не замер пикового CUDA VRAM на Linux. Суммарный пик на целевом сервере ещё нужно измерить.

Измерения первого эксперимента — `reports/catalog_pipeline.json`. Бюджет 0,5 с для пути от ввода до UI пока не подтверждён браузерным замером; вычислительный путь проходит его на этой выборке. Начальный поиск только по целому тексту дал 18/37: после добавления префиксов стало 33/37, поэтому использованный holdout считать диагностическим, а не независимым финальным тестом.

`reports/manual_annotation_queue.jsonl` содержит 180 исходных XLSX-запросов (60 на файл) с происхождением, но **0 проверенных эталонов**. Это очередь экспертам, не готовый тест. Нужны разговорные формулировки, отрицания, неоднозначности, товары вне области, несколько допустимых ответов и «неизвестно». Разбиение делать по семействам/исходным примерам; не разносить перефразировки между настройкой и тестом.

Новый путь проверен тестами без реальных моделей на границах контрактов: отсутствие лексических зависимостей, отсутствие фильтрации гипотезами, точные цитаты/ID/числа, ревизии, подтверждения, полный набор вариантов, ручной fallback и предпочтения. Тестовый адаптер не является измерением качества модели.

Браузерная регрессия `tools/ui_semantic_search_check.mjs` через CDP запущенного Chrome проверяет реальный ввод «молоток», быстрые последовательные правки до «стул на металлическом каркасе» и подтверждение типа. Предварительные совпадения обновляются, после подтверждения показывается настоящая область проверки, исключений JavaScript нет. Это функциональная проверка, а не p95-замер.

Для модели используются короткие технические ID `P…`/`V…`, вычисленные из полного снимка, с сохранённым соответствием устойчивым ссылкам каталога. Это не словарь слов или синонимов; контекст и журнал содержат проверяемую связь с конкретными сущностями.
