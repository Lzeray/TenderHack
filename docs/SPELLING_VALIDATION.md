# Проверка обзора «Исправление опечаток в коротких описаниях товаров» (10.10.2026)

Обзор получен по промту `docs/SPELLING_PROMPT.md`. Проверено двумя способами: утверждения о нашей системе и данных —
кодом и прогоном по снимку КТРУ и выгрузкам; внешние цифры, лицензии и версии — по первоисточникам (README и карточки
моделей скачаны напрямую, `curl`). Сырьё проверки — `reports/exp/spell_validate_ste.txt`, `scratchpad/web` (не в git).

## Итог

Общая рекомендация обзора — остаться на детерминированном словарном конвейере и не ставить нейросеть в путь
запроса — **подтверждается** и данными, и опубликованными замерами. Внешние цифры обзора сходятся с источниками.
Но **диагноз причин** двух примеров неверен для нашей системы, а несколько допущений о данных не выполняются;
это меняет порядок работ.

## Ответы на вопросы обзора (то, что известно нам)

1. Коммерческое использование — решает команда; до решения матрицу kartaslov не используем (только как ориентир).
2. Журнала реальных запросов нет; есть возможность писать журнал решений (`EVENT_LOG`), но пользователей пока нет.
3. Известность — по словарю (`word_is_known`), не по разбору.
4. Идентификатора поставщика нет — делим по производителю.
5. Производитель есть, но это юрлица; бренды надо извлекать.
6. Кириллические бренды («Зубр», «Энкор», «Гранит», «Интерскол») — защищать (белый список из наименований выгрузок).
7. Вопросы уже задаются в интерфейсе; при неотвеченном вопросе поиск идёт по исходной строке (как сейчас).
8. «18о мм» — не трогать (так и сейчас), пометка — по решению команды.
9. GPU есть только на сервере для прогонов (8 ГБ); в рабочем контуре — не гарантирован. Шаг 12 обзора — не сейчас.
10. ё → е и нижний регистр — в нормализаторе для всего текста; в истории преобразований отдельный шаг.
11. Точка отсчёта — `reports/exp/typo_probe_now.txt`: из 25 проб исправно 8 (простые опечатки).
12. Синонимы («железный») — отдельной задачей, как и предлагает обзор.

## Решение команды (10.10.2026)

Порождение всех форм в словарь отклонено: топорно и не масштабируется. Вместо него — **поиск по основе**:
словарь остаётся маленьким (словоформы каталога и их основы); для неизвестного слова ищется близкая основа,
формы 1–2 лемм-кандидатов порождаются только в момент запроса, выбирается ближайшая к набранному слову.
Новая лексика каталога подхватывается автоматически, без пересборки словаря форм.

Порядок работ: 0 стенд оценки → 1 защита токенов → 2 гомоглифы и раскладка → 3 поиск по основе → далее по плану.

## Журнал

### Шаг 0. Стенд оценки (`experiments/spell_eval.py`)

Наборы: A — 884 чистых текста из КТРУ (синтетика без вариантов «-typo»), B — 3 000 реальных наименований отложенных
производителей, где все русские слова есть в словаре; C — синтетика по классам (по 300); F — 15 проб.
Эталон — тот же конвейер (normalize → typos) по чистому тексту. Первая версия стенда считала эталон другой функцией,
для которой единицы («см», «Н·м») — слова, и занижала все классы; базовые цифры ниже — после исправления.

### Шаги 2–3. Гомоглифы, раскладка, поиск по основе

- Нормализатор: слово в основном из кириллицы с латинскими двойниками (a c e o p x y k b h m t) → кириллица;
  размер «ххl» → «xxl»; текст целиком в латинской раскладке → ЙЦУКЕН, если после перевода ≥ 60 % слов — слова
  общего словаря или словоформы каталога (их движок передаёт при запуске); «,» и «.» — буквы «б»/«ю» только перед
  буквой. Замены посимвольные, координаты исходного текста сохраняются; шаги видны в истории преобразований.
- Исправитель: индекс основ каталожных слов (бесловарный стеммер, ~2,2 тыс. словоформ — словарь не расширяется);
  если обычный поиск не дал кандидатов или выбрать нельзя — ближайшая основа (≤ 1 правка) → 1–3 леммы → их формы,
  порождённые в момент запроса. При равных вариантах разных лемм выбирается единственный с тем же окончанием
  (только окончания русских слов и только варианты с той же первой буквой; иначе «кругой» → «дугой», «шкрф» →
  «шарф»).

### Шаг 5. Слитное и раздельное написание (typos 1.3)

- Слитно («шкафдля», «безподлокотников», «мужскаязимняя»): неизвестное слово ≥ 6 букв делится на две части, если
  разбиение единственное и обе части — слова каталога либо одна — служебное слово («для», «с», «без», «на», «из»,
  «в», «под», «от», «до», «по», «и», «или»), а другая — слово каталога ≥ 4 букв. Части не исправляются. Разбиение
  уступает только однозначному исправлению на 1 правку. Токен делится на два с координатами внутри исходного,
  поэтому подсветка и привязка к тексту не ломаются.
- Раздельно («шуруп оверт»): два соседних кириллических слова склеиваются, если одно из них неизвестно (ни
  каталогу, ни словарю, не служебное), а вместе — слово каталога. Два настоящих слова («под ставка») не
  склеиваются.
- Выбор пользователя приоритетен: ключ — исходное написание («шуруп оверт» → «шуруп оверт» оставляет раздельно),
  выбор с пробелом делит токен.
- Стенд: в классе «раздельно» фильтр «получилось настоящее слово» проверял склейку частей, то есть исходное слово, и
  отбрасывал почти все примеры (124 из 300 за 6 000 попыток). Теперь пример отбрасывается, только если обе части —
  настоящие слова. Базовое значение класса от этого не меняется (0 %: склейки не было).
