# Проверка обзора «Исправление опечаток в коротких описаниях товаров» (10.10.2026)

Обзор получен по промту `docs/SPELLING_PROMPT.md`. Проверено двумя способами: утверждения о нашей системе и данных —
кодом и прогоном по снимку КТРУ и выгрузкам; внешние цифры, лицензии и версии — по первоисточникам (README и карточки
моделей скачаны напрямую, `curl`). Сырьё проверки — `reports/exp/spell_validate_ste.txt`, `scratchpad/web` (не в git).

## Итог

Общая рекомендация обзора — остаться на детерминированном словарном конвейере и не ставить нейросеть в путь
запроса — **подтверждается** и данными, и опубликованными замерами. Внешние цифры обзора сходятся с источниками.
Но **диагноз причин** двух примеров неверен для нашей системы, а несколько допущений о данных не выполняются;
это меняет порядок работ.

## Утверждения о нашей системе и данных

| Утверждение обзора | Проверка | Вердикт |
| --- | --- | --- |
| «кругой», «офиссное» не исправляются, потому что известность слова определяется по наличию разбора pymorphy (вопрос 3) | у нас `is_known_word` = `word_is_known` (проверка по словарю): оба слова **неизвестны**. Настоящая причина — словарь опечаток из 2 185 словоформ КТРУ: в нём нет «круглой», «офисное» | **неверно** (причина другая); лечение обзора (порождение форм) при этом верное |
| Порождение форм лемм КТРУ даст «десятки тысяч» форм | 2 185 → 17 639 форм (сущ., прил., причастия), 0,3 с; «круглой», «офисное», «металлическом» появляются | подтверждено (порядок величины чуть меньше) |
| «шкaф» (латинская a) — гомоглиф, нужна таблица замен | токен «шкaф» классифицируется как **код** (смешанный алфавит) и защищён от исправления; при этом кандидат «шкаф» на расстоянии 1 есть | подтверждено; конкретная причина у нас — классификация токена |
| Пример раскладки «ifra lkz jlt;ls» после перевода даёт «шакф», т. е. в нём ещё и перестановка | i→ш, f→а, r→к, a→ф = «шакф»; «шкаф» в раскладке — «irfa». Пример в промте был ошибочным | **подтверждено** (обзор поймал нашу ошибку) |
| «метал» — словарное слово (форма «метать»), «шуруп» известен, «оверт» нет | `is_known_word`: «метал» — да, «шуруп» — да, «оверт» — нет; «мет» тоже «известно» (лемма «мета») | подтверждено; значит, сокращения надо обрабатывать **до** проверки известности — как и предлагает обзор |
| «длинной» — ошибка настоящим словом | «длинной» известно, а лемма «длинный» есть в КТРУ («длинный рукав») | подтверждено; уже исправлено правилом нормализатора (`3b541e5`) |
| Сокращения можно добывать сопоставлением наименования и характеристик одной карточки | «нерж.» → «нержаве…» в характеристиках той же карточки 234/249 (94 %), «эл.» 37/44, «дер.» 35/43, «х/б» 554/682; но **«мет.» — 39/95 (41 %)**, «пласт.» 11/25, «акк.» встречается в 6 карточках | частично: работает для одних сокращений, слабо для других; редкие («акк.») из выгрузок не получить |
| В наименованиях выгрузок есть смешанные алфавиты | 621 различный токен: «cталь», «cтол», «cерый», «cтул», «мужcкой» (латинская c) — и **обратные**: «хl», «ххl», «хххl» (кириллическая х в размере XL) | подтверждено; обратный случай обзор не учёл — размеры «ХХL» нужно приводить к латинице, а не к кириллице |
| Белый список брендов — из поля «производитель» (вопрос 5) | поле содержит юрлица: «ЗАКРЫТОЕ АКЦИОНЕРНОЕ ОБЩЕСТВО ЗУБР ОВК», «ООО "ФАБРИКА ВИЛАН"»; 19 135 значений | **не выполняется напрямую**: бренды надо извлекать (латинские слова наименований, очищенные названия юрлиц) |
| Деление данных по поставщикам (вопрос 4) | идентификатора поставщика в выгрузках нет (6 столбцов: ID, наименование, модель, производитель, страна, характеристики) | **не выполняется**: делить по производителю, как уже сделано в оценке уровня 2 |
| В единицах с точкой («мм.», «шт.») — риск для сокращений | самые частые «xxx.» в наименованиях: «мм.» 1 850, «шт.» 1 190, «см.» 1 116, «арт.» 916 | подтверждено |
| «Сервис уже использует порт SymSpell» | своя реализация индекса удалений (`nlp/typos.py`); `symspellpy` не установлен | неточно; на выводы не влияет |

## Ответы на вопросы обзора (то, что известно нам)

1. Коммерческое использование — решает команда; до решения матрицу kartaslov не используем (только как ориентир).
2. Журнала реальных запросов нет; есть возможность писать журнал решений (`EVENT_LOG`), но пользователей пока нет.
3. Известность — по словарю (`word_is_known`), не по разбору.
4. Идентификатора поставщика нет — делим по производителю.
5. Производитель есть, но это юрлица; бренды надо извлекать.
6. Кириллические бренды («Зубр», «Энкор», «Гранит», «Интерскол») — защищать (белый список из наименований выгрузок).
7. Вопросы уже задаются в интерфейсе; при неотвеченном вопросе поиск идёт по исходной строке (как сейчас).
8. «18о мм» — не трогать (так и сейчас), пометка — по решению команды.
9. GPU есть только на сервере для прогонов (8 ГБ); в рабочем контуре — не гарантирован. Шаг 12 обзора — не сейчас.
10. ё → е и нижний регистр — в нормализаторе для всего текста; в истории преобразований отдельный шаг.
11. Точка отсчёта — `reports/exp/typo_probe_now.txt`: из 25 проб исправно 8 (простые опечатки).
12. Синонимы («железный») — отдельной задачей, как и предлагает обзор.

## Скорректированный план (с учётом проверки)

Порядок обзора разумен; меняется содержание шагов 2–3 и добавляются два пункта.
