# Гипотеза: КПГЗ/СПГЗ для отбора СТЕ после фильтрации КТРУ

Дата: 10.10.2026. Основа кода: `origin/main` на `33751bb`, объединённый в `aydar`
коммитом `a020e7e`. Модули `ktru_assist/` и React-фронтенд совпадают с этой версией main.
Эксперимент не подключён к HTTP-выдаче и не присваивает товарам нормативные коды.

## Требования

Перечитана презентация организаторов `Презентация_Задачи_Хакатон_Казань_20261009_1900_pdf.pdf`:

- стр. 2–5: унификация характеристик, значений и единиц, постепенное сужение до конечного КТРУ,
  конкретные уточнения при неоднозначности и объяснение ошибок;
- стр. 6–7: Linux, веб-интерфейс, ограничения на платный поиск и проприетарные модели;
- стр. 10–13: статус и сроки КТРУ, работа только с actual XML; фактические свойства СТЕ
  и типовые свойства категорий — разные данные; КТРУ имеет приоритет.

Граница эксперимента: выбранная область КТРУ остаётся фиксированной при сравнении товарных наборов.
КПГЗ/СПГЗ — дополнительные сведения о товарах и категориях, не новый распознаватель КТРУ.

## Что установлено по внешним источникам

1. [Аналитический центр Москвы](https://ac.mos.ru/standards/): КПГЗ — классификатор,
   СПГЗ — справочник предметов государственного заказа; позиции гармонизированы с федеральным
   каталогом, используются унифицированные характеристики. Это подтверждает возможность связи,
   но не уникальность конечного КТРУ по категории.
2. [Приказ ДЭПиР от 08.06.2023 № ДПР-ПР-81/23, приложение 1](https://base.garant.ru/407033232/53f89421bbdaf741eb2d1ecc4ddb4c33/):
   - п. 2.4: в гармонизированную позицию КПГЗ включается код КТРУ;
   - п. 2.8: карточка СПГЗ содержит КПГЗ, ОКПД2 конечного уровня, единицы ОКЕИ,
     а гармонизированная позиция — также код КТРУ;
   - п. 3.4: гармонизированные позиции должны включать обязательные характеристики
     и значения соответствующего КТРУ, возможны дополнительные характеристики.
   Следовательно, **официальная прямая связь предусмотрена**, но её надо получить из полных карточек.
   ОКПД2 сам по себе её не заменяет.
3. [Доступный сторонний поиск СПГЗ](https://kuplushki.ru/tools/spgz/) возвращает название,
   `global_id`, КПГЗ, ОКПД2, ОКЕИ. Получены все страницы результатов трёх запросов:
   «молоток» — 26, «стул» — 70, «перчатки» — 70, итого 166 разных позиций.
   В ответах нет конечного кода КТРУ и характеристик позиции. Это исследовательское зеркало,
   не нормативный источник и не полный справочник СПГЗ.
4. Полная загрузка первичных карточек заблокирована доступностью источников:
   `https://eaist.mos.ru/api/kpgz/list` — HTTP 403; `https://zakupki.mos.ru/` — timeout TLS.
   Запросы не обходят авторизацию. URL, время получения, статусы и SHA-256 сохранены.

Сырые ответы: `data/exp_reference_sources.json` (локальный игнорируемый файл).
Переносимый снимок с 166 позициями и метаданными источников:
`reports/ste_reference_ablation_sources.json`.

## Что найдено в предоставленных товарах

- Обработаны все **299 986 СТЕ** из трёх XLSX и все **106 652 строки** типовых свойств.
- Выделены **617 конечных категорий КПГЗ**, **32 456 разных ID характеристик СПГЗ**.
  467 строк не содержат валидного кода КПГЗ; их нельзя использовать как категорийные записи.
- Отдельной колонки категории в товарном листе нет, но она встречается внутри фактических
  характеристик: например, `Виды стульев Стулья на металлическом каркасе`.
  Это уточняет прежнее предположение, что связи между листами вообще нет.
- Категорию удалось вывести по явным терминальным фактам у **103 695 СТЕ (34,57%)**:
  инструменты — 631; мебель — 55 917; одежда — 47 147.
  Название товара и соседство строк Excel при этом не используются.
- Широких фактов вроде «Вид продукции: Товары» недостаточно. Неполные, противоречивые,
  неоднозначные и неизвестные значения выделены отдельно. Это автоматическое сопоставление
  по данным выгрузки, а не независимая ручная разметка правильной категории.
- ID из колонки «ID связанной эталонной характеристики СПГЗ» остаются ID **характеристик**.
  Их нельзя считать `global_id` позиции СПГЗ или кодами КТРУ.

## Метод сравнения

`experiments/ste_reference.py` выполняет девять сравнений:

1. Получает полный набор действующей `SteSearch.search()` по названию/атрибутам.
2. Фиксирует активные конечные позиции выбранного наименования КТРУ; заданные атрибуты
   проверяет существующим `check_feature`. Этот набор кодов не зависит от товарного отбора.
3. Сопоставляет КТРУ с полученными СПГЗ только по **полному совпадению названия и ОКПД2**,
   затем извлекает КПГЗ. Основание явно отмечено как гипотеза стороннего источника.
4. Делит товары на подходящую, другую и неизвестную категорию. Строгая ветка берёт первую;
   мягкая исключает только явно другую категорию. Полные ID обеих веток сохранены.
5. В подходящей категории сравнивает фактические свойства со штатным валидатором КТРУ:
   сначала прямые названия, затем явные связи названий характеристик СПГЗ.
   Учитываются единицы и числовые границы; обязательное отсутствующее свойство — `unknown`.
   Проверяются также поставленные факты по необязательным распознанным свойствам.
   Противоречивые дубликаты, неподдержанные форматы и неоднозначные связи не дают `checked`.

`checked` здесь означает проверенные сопоставленные факты и наличие обязательных свойств
хотя бы одной фиксированной позиции. Не проверяются нераспознанные свойства, содержимое
коммерческой модели и истинность исходных данных; официальная связь СТЕ → КТРУ не доказана.

## Результат и решение

Полная таблица: `reports/ste_reference_ablation.md`; наборы ID и реальные примеры:
`reports/ste_reference_ablation.json`.

- Стул на металлическом каркасе: **13 139 → 1 774** в подходящей категории;
  5 628 имеют другую категорию, 5 737 остаются неизвестными.
  Из 1 774: 533 прошли проверки, 306 противоречат характеристикам, 935 требуют уточнения.
- Стул на деревянном каркасе: **15 033 → 510** в подходящей категории;
  183 прошли проверки, 77 противоречат характеристикам, 250 требуют уточнения.
- Молоток слесарный 500 г: **52 → 0** при строгом требовании категории; все 52 неизвестны.
  Это отсутствие категорийных фактов, а не доказательство неподходящего товара.
- Перчатки из полимерных материалов: **7 047 → 675** по категории;
  98 прошли проверки, 229 противоречат характеристикам, 348 требуют уточнения.
- У категории трикотажных защитных перчаток в выгрузке нет категореобразующих свойств:
  прямое категорирование этой ветки данным методом не обеспечено.
- Добавление связей характеристик СПГЗ не увеличило количество проверенных товаров;
  выявило дополнительные противоречия: металлостулья 535 → 533 проверенных,
  деревянные стулья 184 → 183, полимерные перчатки 99 → 98.
  Меньший набор не доказывает рост точности без ручной проверки.

**Вывод:** категорийная связь полезна, особенно в мебели, но универсальный строгий фильтр
по текущим данным непригоден. Он скрывает товары без категории и не гарантирует соответствие
всем характеристикам. Поэтому эксперимент не включён в основной товарный endpoint.

Для перехода к выдаче «только подходящих» нужны полные гармонизированные карточки
`СПГЗ(global_id, КПГЗ, код КТРУ, характеристики, статус/версия)` и фактическая категория
или свойства для СТЕ без неё. Затем — ручная проверка сохранённых положительных,
отрицательных и неизвестных примеров. Рабочий подбор КТРУ остаётся верхним ограничением.

  базовой выдачи; классификация охватывает ровно 299 986 строк товаров.
