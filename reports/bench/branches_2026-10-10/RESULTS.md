## Выводы

- **Безопасность (неверные автокоды) — лучше всех `Lenaz`**: 1 неверный автокод из 313 обычных запросов test
  (точность 99,3%), 98% противоречий без кода, 77 неверных автокодов на метаморфных наборах против 105–113 у остальных.
  У неё же больше всего верных кодов сразу (@0 45,1%, полное описание → код 74,6%) и меньше всего лишних вопросов.
- **`matvey_develop` лучше всех доводит до кода в диалоге** (@2 84,4%, hit@3 93,9%, MRR 0,919), лучше всех держит
  слитные слова (45% против 22–26%), ленивый ввод (78%) и переформулировки (`same_as` в `invariance` 97,1%) и работает
  быстрее всех (p50 6 мс). По неверным автокодам (5 на test) — на уровне MVP.
- **`aydar` (режим `rules`)** близок к MVP: на 2 неверных автокода меньше на test, но хуже всех на противоречиях (91,2%),
  а на `manual_dev` / `manual_holdout` — единственная ветка, которая не всегда доводит до кода уточнениями (88,9% / 66,7%).
- **Общие слабые места всех веток**: `lazy_numbers` — 52–61 неверных автокодов («больше N» / «меньше N» принимаются
  как точное N); `multi_item` — 15–31 автокодов на запрос с двумя товарами (у `Lenaz` меньше всех); слитные слова.
- `Lenaz` уступает остальным на `number_errors` (61,3% против 66–68%): ошибочно записанные числа («0180 мм», «1 80 мм»)
  чаще принимаются молча (`no_feature` 63,7%), хотя неверных автокодов там 0.

## Как получено

- Для каждой ветки — отдельная рабочая копия на указанном коммите; каталог `benchmark/` заменён на `benchmark/` из `main`
  (плюс `lazy_numbers.jsonl`), код системы (`ktru_assist`) — свой у каждой ветки. База — общий `data/ktru.sqlite`.
- `matvey_develop` читает статистику выгрузок СТЕ (`data/ste_stats.sqlite`, в git её нет). Она пересобрана сборщиком
  самой ветки (`ste_stats` 1.1) из `Примеры выгрузок`:
  `python -m ktru_assist.catalog.ste_stats --src "Примеры выгрузок" --db data/ktru.sqlite --out data/ste_stats.sqlite`.
  Со старым файлом (1.0) у ветки падал тест `test_relation_warning_between_named_values`.
- Команды прогона в каждой копии:

```bash
MM=$(ls benchmark/metamorphic/suites/*.jsonl)
python -m benchmark.run --adapter ktru:core --dialog --suites all --out v1_core.json
python -m benchmark.run --adapter ktru:core --dialog --suites $MM --out v1_mm.json
python -m benchmark.independent.run --adapters ktru:core --no-baselines \
    --suites natural contradictions out_of_scope $MM --hide-test-cases --out v2.json
python -m pytest -q tests          # на чистой копии ветки, без подмены benchmark/
```

- Отчёты по веткам: `<ветка>/v1_core.md`, `<ветка>/v1_metamorphic.md`, `<ветка>/v2.md`; агрегаты всех метрик —
  `summaries.json` (строки кейсов не сохранялись: test-кейсы заморожены и скрыты).
